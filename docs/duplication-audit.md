## Summary

- **~55 confirmed duplication clusters** survived adversarial verification, spanning ~19,000 duplicated lines. Roughly 40% of that is test/build/infra scaffolding (Dockerfiles, vitest configs, testkits, CI jobs) rather than product code.
- **8 new packages** are justified; **12 existing `@duncit/*` packages** just need extending. A further **14 clusters are pure adoption gaps** — the package already exports the thing and the call sites never migrated (section 3).
- **Biggest single offender: portal boot boilerplate.** `GoogleSignInButton` (18 byte-copies), `AppShell.tsx` (17), `main.tsx` (17), `url-configs.ts` (18) and `apollo.ts` (16 byte-identical) are ~2,800 LOC repeated across the same 18 workspaces — all of which already depend on `@duncit/shell`. Zero new dependencies, zero Docker changes.
- **Highest-risk offender: money math.** The GST-inclusive breakup formula exists in 6 independent implementations across server, finance portal, mWeb (×2) and native ([server/src/modules/finance/finance/breakdown.math.ts:127](server/src/modules/finance/finance/breakdown.math.ts#L127), [portals/finance/src/pages/calculators/pod-profit/useCalculator.ts:40](portals/finance/src/pages/calculators/pod-profit/useCalculator.ts#L40), [app/mobile-app/src/utils/checkout-math.ts:41](app/mobile-app/src/utils/checkout-math.ts#L41)), and `round2` is defined 18 times in two behaviourally different variants.
- **Duplication has already produced live defects**, not just maintenance cost: onboarding's `url-configs.ts` advertises ads-portal's hostname; 4 server services build search regexes without escaping user input; the client's `timestamp` field is silently dropped by the log ingest; all 17 portals retry **mutations** up to 6× while mWeb's fork explicitly refuses to; staging Astro builds POST telemetry to the production ingest.
- **The server is the hard boundary.** `server/src` imports zero `@duncit/*` packages and `server/Dockerfile` COPYs no `packages/*` — every server-side cluster must land as a server-internal module, not a package.

## Do NOT extract

- **List-page CRUD scaffold across 8 portals** — the shared residue is `const refetchRef = useRef(...)` plus `refetchRef.current?.()`; the ref contract is already `@duncit/table`'s. ## Migration order

Ranked by safety × value. Pure zero-dep logic first, UI and codegen last. Every PR goes **feature branch → `staging` → PR to `main`** (rule 32), and the pre-commit hook bumps the app version on *every* commit — batch commits so you don't push a version the Play Store build won't match (rule 33).

1. **Pure deletions / adoption (no new code).** `@duncit/utils` `parseApiError` + `downloadBase64File` in mWeb (15 + 5 call sites); `@duncit/app-settings` `useFeatureFlag` in mWeb; delete the 0-byte and dead files. *Gotcha:* the download helper's **argument order is different** (`(base64, filename, mime)` vs mWeb's `(filename, base64, mime)`) — swapping the import without swapping args names the file after its own contents. 4 mWeb tests `vi.mock` the local `useFeatureFlag` path and will silently stop mocking.

## Risks & caveats

- **Section 13 (mobile-local, crm-local, onboarding-local) and the C7 cluster generally are PLAUSIBLE, not adversarially verified.** They came from a completeness sweep with file/line evidence but were not put through the same second-pass verification as L1–L6. Re-diff before acting, especially C7-01 (the 50-file mobile modal count) and C7-11 (the payment gateway divergence).
- **`@duncit/pod-audit` is a 2-workspace cluster.** Under a strict 3-occurrence rule it does not qualify; it survives only because `PodAuditDetailDialog.tsx` is byte-identical. Cut it first if the batch must shrink. The two GraphQL root fields are deliberately differently-authorised — the query builder must stay parameterised.
- **`@duncit/mjml-editor` is gated on a decision, not a diff.** Rule 28 says email templates live only in the tech portal; if `portals/crm/src/pages/email-templates/**` is legacy, deleting it leaves 2 occurrences and **deletion beats extraction**. Determine that before extracting on the strength of a copy that shouldn't exist.
- **The `@duncit/gql-types` adoption (section 3) is not a one-line import swap.** It is currently a `devDependency` imported almost exclusively from `__tests__/`, and `app/mweb`/`app/mobile-app` don't list it at all — adopting it in `src/` promotes it to a prod dependency in 7+ workspaces. Do it enum-by-enum. Also: `packages/category`'s lower-cased `CategoryLevel` is a genuinely *different* domain type — rename it, don't merge it.
- **Raw-TS package resolution is unproven for build configs.** Every `@duncit/*` package exports `./src/index.ts` with no build step. That is fine for app code but untested for a preset imported *by* a vite/vitest config, which vite bundles with esbuild. Prototype on one portal (step 8) before committing to the pattern.
- **Coverage gates will move in both directions.** `app/mobile-app` (100/100/100/100), `packages/utils`, `packages/shell` (statements/functions/lines 100, branches −3) and several portals gate at 100. Moving code out shrinks a denominator; moving jsdom stubs *in* makes new branches reachable. Every step that touches a gated workspace needs `test:coverage`, not just `typecheck`.
- **The Docker COPY gotcha is the single most likely way this batch breaks.** Any new `@duncit/*` dependency on `app/mobile-app` requires COPY lines in **both** `Dockerfile` and `Dockerfile.android`; on a website, both the package.json whitelist **and** the source whitelist; on the server, both stages of `server/Dockerfile` plus the `pnpm install --filter server` step. All of these pass locally and fail only in the deploy build (precedent: commit `8a5f6d2e`).
- **Several "refactors" are actually behaviour changes and must be flagged in their PRs:** the portal mutation-retry fix, mWeb/partners-app starting to honour the admin date format, mobile's gateway fallback, the pod-type label separator, the PDF brand-red unification, the whatsapp page-size cap, and any `fmtDate` migration (rendered strings change, breaking snapshot-ish assertions).
- **Localization (rule 38) blocks more of this than it looks.** The Google sign-in fallback, the approve/reject copy, the withdraw validation messages, the pod-type labels, the refund timeline strings, the password field's `aria-label`, the payment error strings and the Astro headline copy are all hardcoded English today. Moving them into a package makes them *harder* to localize later — create the keys in `packages/i18n/src/bundles.ts` and run **Import app keys** first, or the extraction cements the violation.
