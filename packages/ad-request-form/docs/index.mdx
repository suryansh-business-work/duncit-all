## Why this exists

Two surfaces submit the same `submitAdRequest` mutation: the Ads portal's **Create Ad**
page (`portals/ads-portal/src/pages/create-ad-page/CreateAdPage.tsx`) and the Partner
portal's **Run ad** dialog on a product row
(`portals/partners-app/src/pages/list-products-page/RunAdDialog.tsx`). Before this package
each one owned a form, a Zod schema and its own copy of the placement list — so a rule the
server enforces (title 3–120, duration 1–30 days, http(s) redirect only) had to be fixed
twice, and a new placement had to be added twice.

The vocabulary moved here too. `portals/ads-portal/src/pages/ads/ad-options.ts` is now a
one-line `export * from '@duncit/ad-request-form'` re-export, kept only so existing
relative imports in that portal keep resolving.

## Use it

From `CreateAdPage.tsx`, verbatim in shape:

```tsx
import {
  AdRequestForm,
  EstimateCard,
  blankAdRequestValues,
  toSubmitAdRequestInput,
  type AdRequestFormValues,
} from '@duncit/ad-request-form';

const [draft, setDraft] = useState<AdRequestFormValues>(blankAdRequestValues);

const handleSubmit = async (values: AdRequestFormValues) => {
  const result = await submitAdRequest({
    variables: { input: toSubmitAdRequestInput(values) },
  });
  notifySuccess(`Ad request submitted · Trace ID ${result.data?.submitAdRequest.trace_id}`);
};

<AdRequestForm
  initialValues={draft}
  busy={saving}
  errorMessage={formError}
  onValuesChange={setDraft}
  onSubmit={handleSubmit}
/>
<EstimateCard
  pricing={pricingData?.adPricing}
  loading={pricingLoading}
  position={draft.position}
  durationDays={draft.duration_days}
/>
```

Note `blankAdRequestValues` is passed **as a function** to `useState` — it calls
`new Date().toISOString()` for `start_at`, so calling it during render on every pass would
produce a new default each time.

## Worked examples

### `blankAdRequestValues()`

```js
{
  ad_title: '',
  ad_description: '',
  ad_type: 'IMAGE',
  media_url: '',
  position: 'AUTO',
  start_at: <the moment you called it>,   // new Date().toISOString() — fresh on every call
  duration_days: 7,
  redirect_url: '',
  target_audience: ''
}
```

That `start_at` is why it is a **function**, and why `useState(blankAdRequestValues)` passes the
reference rather than calling it.

### `toSubmitAdRequestInput(bakingKitAd)`

```js
{
  ad_title: 'Monsoon Baking Kit — 20% off',
  ad_description: 'Flour, banneton and a scraper in one box. Delivered across Bengaluru in 48 hours.',
  ad_type: 'IMAGE',
  media_url: 'https://ik.imagekit.io/duncit/ads/monsoon-baking-kit.jpg',
  position: 'EXPLORE_SCROLL',
  start_at: '2026-08-10T00:00:00.000Z',
  duration_days: 14,
  redirect_url: 'https://duncit.com/shop/monsoon-baking-kit',
  target_audience: 'Home bakers in Bengaluru, 22-45'
}
```

With both optionals blank (`redirect_url: ''`, `target_audience: ''`) the two keys are **omitted
entirely**, not sent as empty strings:

```js
{
  ad_title: 'Monsoon Baking Kit — 20% off',
  ad_description: 'Flour, banneton and a scraper in one box. Delivered across Bengaluru in 48 hours.',
  ad_type: 'IMAGE',
  media_url: 'https://ik.imagekit.io/duncit/ads/monsoon-baking-kit.jpg',
  position: 'EXPLORE_SCROLL',
  start_at: '2026-08-10T00:00:00.000Z',
  duration_days: 14
}
```

### Pricing the same request

```js
const key = AD_PRICING_KEY_BY_POSITION[bakingKitAd.position];
// 'explore_scroll_per_day'

adPricing[key];                                  // 320
adPricing[key] * bakingKitAd.duration_days;      // 4480
formatAdCost(4480, adPricing.currency_symbol);   // '₹4,480'
formatAdCost(320.5, '₹');                        // '₹320.50'
```

Whole amounts render with no decimals, fractional with two — that split is the whole reason
`formatAdCost` exists rather than a bare `formatMoney` call.

### Labels

```js
adPositionLabel('EXPLORE_SCROLL');   // 'Explore Scroll'
adPositionLabel('NEWSLETTER');       // 'NEWSLETTER'  ← unknown values pass through unchanged
adTypeLabel('VIDEO');                // 'Video'
```

`adPositionLabel` never throws on an unrecognised placement; it returns the raw enum. If a portal
starts displaying SCREAMING_SNAKE in the UI, that is a placement missing from `AD_POSITION_OPTIONS`.

### `AD_STATUS_COLORS`

```js
{ PENDING: 'warning', APPROVED: 'info', LIVE: 'success', REJECTED: 'error', EXPIRED: 'default' }
```

Typed `StatusColorMap` from `@duncit/ui`, so it drops straight into the shared status chip.

### `adRequestSchema.safeParse(...)` on a bad request

Parsing the sample with `ad_title: 'Ad'`, `media_url: ''`, `start_at: '2020-01-01T00:00:00.000Z'`,
`duration_days: 45`, `redirect_url: 'duncit.com/shop'`:

```js
[
  { path: 'ad_title',      message: 'Ad title must be at least 3 characters' },
  { path: 'media_url',     message: 'Upload the ad media' },
  { path: 'start_at',      message: 'Ad start date must be today or later' },
  { path: 'duration_days', message: 'Ad duration can be at most 30 days (1 month)' },
  { path: 'redirect_url',  message: 'Redirect URL must be a valid http(s) link' }
]
```

`toSubmitAdRequestInput` calls `.parse`, not `.safeParse` — it **throws** on invalid values. It is
the last line of defence after the resolver, not a validation entry point.

## Props / API

### `<AdRequestForm>` — `AdRequestFormProps`

| Prop | Type | Required | Default | Meaning |
| --- | --- | --- | --- | --- |
| `initialValues` | `AdRequestFormValues` | yes | — | Seed values for the RHF form. |
| `busy` | `boolean` | yes | — | Disables the submit button while the mutation runs. |
| `errorMessage` | `string \| null` | no | `undefined` | Server error rendered above the actions. |
| `onValuesChange` | `(values: AdRequestFormValues) => void` | yes | — | Fires on every `watch()` tick — this is what feeds `EstimateCard`. |
| `onSubmit` | `(values: AdRequestFormValues) => Promise<void> \| void` | yes | — | Called with schema-valid values. |
| `submitLabel` | `string` | no | `undefined` | Overrides the submit button text (e.g. `'Submit Product Ad'`). |

### `<EstimateCard>`

| Prop | Type | Required | Default | Meaning |
| --- | --- | --- | --- | --- |
| `pricing` | `AdPricing \| null` | no | `undefined` | The `adPricing` payload. Missing or null renders the skeleton. |
| `loading` | `boolean` | yes | — | Renders three skeleton rows instead of figures. |
| `position` | `AdPosition` | yes | — | Which per-day rate to read. |
| `durationDays` | `number` | yes | — | Multiplier; `1` renders "1 day", anything else "N days". |

### `<AdMediaField>`

| Prop | Type | Required | Default | Meaning |
| --- | --- | --- | --- | --- |
| `adType` | `AdMediaType` | yes | — | Scopes the shared `MediaPickerDialog` to images or video. |
| `value` | `string` | yes | — | Current media URL; drives the inline preview. |
| `onChange` | `(url: string) => void` | yes | — | Receives the picked URL. |
| `error` | `boolean` | no | `undefined` | Error styling. |
| `helperText` | `string` | no | `undefined` | Text under the field. |
| `required` | `boolean` | no | `undefined` | Renders the red required asterisk. |

### Functions and constants

| Export | Signature / value | Meaning |
| --- | --- | --- |
| `adRequestSchema` | `ZodObject` | The contract; mirrors the server's `SubmitAdRequestInput` rules. |
| `blankAdRequestValues` | `() => AdRequestFormValues` | Factory — `start_at` is "now", so never a shared constant. |
| `toSubmitAdRequestInput` | `(values) => SubmitAdRequestInput` | Re-parses, then maps; **throws** on invalid input. |
| `AD_MEDIA_TYPE_OPTIONS` | `[{ value, label }]` | `IMAGE`, `VIDEO`. |
| `AD_POSITION_OPTIONS` | `[{ value, label }]` | The nine placements, in menu order. |
| `AD_STATUS_OPTIONS` | `[{ value, label }]` | `PENDING`, `APPROVED`, `LIVE`, `REJECTED`, `EXPIRED`. |
| `AD_PRICING_KEY_BY_POSITION` | `Record<AdPosition, AdPricingRateKey>` | Placement → pricing field. Use it; do not lower-case the enum. |
| `AD_STATUS_COLORS` | `StatusColorMap` | Status → MUI chip colour. |
| `adPositionLabel` | `(position: string) => string` | Label, or the raw value if unknown. |
| `adTypeLabel` | `(type: string) => string` | Label, or the raw value if unknown. |
| `formatAdCost` | `(value: number, symbol: string) => string` | `formatMoney` with the whole/fractional decimals rule. |

### Schema rules, in full

| Field | Rule | Message on failure |
| --- | --- | --- |
| `ad_title` | required, 3–120 | `Ad title must be at least 3 characters` |
| `ad_description` | required, 10–1000 | `Ad description must be at least 10 characters` |
| `ad_type` | `IMAGE \| VIDEO` | `Ad type is required` |
| `media_url` | trimmed, min 1 | `Upload the ad media` |
| `position` | one of the nine placements | `Ad position is required` |
| `start_at` | parseable date, today or later | `Ad start date must be today or later` |
| `duration_days` | integer 1–30 | `Ad duration can be at most 30 days (1 month)` |
| `redirect_url` | optional; `http:`/`https:` only | `Redirect URL must be a valid http(s) link` |
| `target_audience` | optional, ≤ 500, defaults to `''` | `Target audience must be 500 characters or fewer` |

## Live preview

No live preview here yet, though `EstimateCard` is the closest thing in this set to previewable —
it takes four plain props, renders pure MUI plus `InfoRow` from `@duncit/ui`, and needs no Apollo,
no router and no form context. `docs-site` has the `<Preview>` island runtime; what is missing is
`@duncit/ad-request-form` in its dependencies.

When that lands, add two `<Preview>` blocks: `<EstimateCard pricing={adPricing} loading={false}
position="EXPLORE_SCROLL" durationDays={14} />` — which renders the `₹4,480` computed above — and
the same card with `loading` true, so the skeleton state is visible.

`AdRequestForm` itself is a heavier lift: it pulls `@mui/x-date-pickers` and `@duncit/media-picker`,
so previewing it means a `LocalizationProvider` in the island and a picker that opens against real
upload config. Do the estimate card first.

## `onValuesChange` is the whole point of the split

The form and the estimate are separate components on purpose: the estimate has to react to
`position` and `duration_days` while the user is still typing. `AdRequestForm` subscribes to
RHF's `watch()` and pushes the whole value object up through `onValuesChange`; the page holds
that as state and feeds `EstimateCard`. Do not try to render the estimate inside the form —
the Partner dialog lays them out side by side in its own `Grid`, and the Ads page makes the
estimate `position: sticky`.

`toSubmitAdRequestInput` re-runs `adRequestSchema.parse` before mapping. That is deliberate:
it normalises `start_at` to an ISO string and drops empty `redirect_url` / `target_audience`
rather than sending `''`, which the server would treat as a supplied value.

## Pricing keys — use the map, do not build the string

The `AdPricing` payload has one field per placement (`home_bottom_per_day`, …). Resolve it
with `AD_PRICING_KEY_BY_POSITION[position]`. Lower-casing the enum value works today by
coincidence and breaks the first time a placement name stops being a straight snake_case of
its enum.

`formatAdCost(value, symbol)` wraps `formatMoney` from `@duncit/utils` with the ads rule:
whole amounts render with no decimals, fractional ones with two. Use it for every ad money
figure so the estimate and the approval queue agree.

## A live duplicate: `portals/marketing/src/lib/ad-positions.ts`

The Marketing portal (Ads approvals + Ads pricing settings) still carries its own
`AdPosition` union, its own `AdPricingPriceField` union and its own `AD_POSITIONS` array with
the same nine labels. It predates this package and has not been migrated. It is a real drift
risk — adding a placement here without editing that file leaves the pricing settings page
unable to price it. If you add a placement, change both, or better, migrate Marketing onto
`AD_POSITION_OPTIONS` + `AD_PRICING_KEY_BY_POSITION` in the same change.

`AD_STATUS_COLORS` is typed `StatusColorMap` from `@duncit/ui`, so it drops straight into the
shared status chip — do not hand-map statuses to MUI colours at the call site.

## Peer dependencies

MUI, `@mui/x-date-pickers`, `react-hook-form`, `@hookform/resolvers`, `zod` and `date-fns` are
**peers**, not dependencies — the consuming portal supplies them so there is exactly one React
and one MUI in the tree. `@duncit/forms`, `@duncit/ui`, `@duncit/media-picker` and
`@duncit/utils` are real workspace dependencies; a portal adopting this package must have
those resolvable, and any Dockerfile building it needs their `package.json` files copied in.

This is an MUI package. It is web-only by construction and has no native twin — the mobile app
does not sell ads.

## Coverage

`vitest.config.ts` sets no thresholds, so this package is **not** on the 100% gate. The
schema is exercised by `src/ad-request.types.test.ts`; the real form flows are covered from
the consuming portals (`portals/ads-portal/__tests__/unit-tests/CreateAdPage.test.tsx`).
