Every image and file uploaded to Duncit is reviewed by an AI model. This
package is the notice that says so: a chip beside the upload control, and an
informational dialog behind it.

There is exactly one place each half of it is decided:

- **What it says** — AI Portal → AI Monitoring → **Settings**. Any field left
  blank falls back to the localized `aiMonitoring.*` copy shipped in
  `@duncit/i18n`, so an untouched setting still follows the reader's language.
- **What it did** — AI Portal → AI Monitoring → **Logs**. Every check is one
  row: the image, who uploaded it, when, how far the check got, what the model
  said, why, what was done about it, and which surface and folder it came from.

## Where the chip goes

Beside anything that accepts an image or a file. In mWeb and the portals every
such control routes through `@duncit/media-picker`, so the chip is placed once
per field there and reaches all eighteen surfaces:

```tsx
import { AiMonitoringChip } from '@duncit/ai-monitoring/mui';

<Stack direction="row" spacing={1} alignItems="center">
  <Typography variant="caption">{hint}</Typography>
  <AiMonitoringChip />
</Stack>;
```

The chip renders nothing when an operator turns the notice off, and needs no
props: it reads the config itself through a public, Redis-cached query, so a
page with six upload fields still makes one request.

## Why the root is framework-free

The native app is a standalone npm project; Metro resolves a linked package's
peer imports by walking up from `packages/<name>/`, which finds nothing in the
Docker build. So the root exports no React at all — only the copy resolution
and the query text — and the app renders its own Tamagui chip over
`resolveAiMonitoringCopy`. Rule 40: share the logic, never the UI.

```ts
import { resolveAiMonitoringCopy } from '@duncit/ai-monitoring';

const copy = resolveAiMonitoringCopy(config, t);
// copy.chipLabel, copy.title, copy.intro, copy.points, copy.footnote, copy.dismissLabel
```

`config` is `null` until the query answers (and forever, offline). That is the
normal case, not an error case: the fallback copy is complete on its own.

## Adding a bullet to the dialog

1. Add the key to `AI_MONITORING_BUNDLE` in `packages/i18n/src/bundles/ai-monitoring.ts`.
2. Add a literal `t('aiMonitoring.<key>')` line to `aiMonitoringFallbackCopy`.
3. Press **Import app keys** in Admin → Localization → Translations.

Do not compose the key from a variable — the Shared Gates check greps for the
literal, and a composed key is invisible to it.

## The motion language

AI Monitoring moves, and it moves the same way everywhere: a person learns the
signal once instead of per screen. There are three states and one badge.

| State | What it looks like | What renders it |
| --- | --- | --- |
| Idle, on a flat control | a band of the AI gradient crossing it, spark turning | `AiMonitoringChip` |
| Idle, on a gradient control | the colour sliding under it, spark turning | `AiMonitorPill` |
| A check is running | the badge breathing and emitting rings, a bar scanning | `AiProcessingOverlay`, `AiProcessingInline` |

The badge itself is `AiMonitorGlyph` — one drawing, at four sizes, so the chip,
the dialog it opens, the pill on a pod row and the wait behind Create Pod are
visibly the same feature.

```tsx
import { AiMonitorGlyph, AiMonitorPill, AiProcessingOverlay } from '@duncit/ai-monitoring/mui';

<AiMonitorPill label={t('shell.podMonitoring.aiMonitoring')} onClick={openTrail} />;

<AiProcessingOverlay
  open={publishing}
  title={t('mweb.createPod.aiMonitoringTitle')}
  note={t('mweb.createPod.aiMonitoringNote')}
  hold={t('mweb.createPod.aiMonitoringHold')}
/>;
```

The processing views hold **no copy of their own**: Create Pod's wording is not
a listing's wording, so the caller passes the sentences, exactly as
`AiMonitoringDialog` takes its `copy`.

### Timings live in `@duncit/utils`, not here

`AI_MONITOR_MOTION` sits beside `AI_MONITOR_GRADIENT`, because the native app
animates the same badge with `Animated` and cannot import this package's MUI
half. Both sides read the durations from there; a duration typed twice is two
features that merely share a palette.

```ts
import { AI_MONITOR_MOTION, AI_MONITOR_RINGS } from '@duncit/utils';

AI_MONITOR_MOTION.breatheMs; // 1800 — the badge, on web and on native
AI_MONITOR_RINGS; // the lead ring and the one half a flight behind it
```

### Every animation can be switched off

Nothing sets `animation` directly. It goes through `aiMotion`, which pairs the
animation with `@media (prefers-reduced-motion: reduce) { animation: none }` —
this is a notice a person is meant to READ before they upload something, and a
shimmer they cannot stop is a reason to look away from it.

```ts
import { aiMotion, aiBreathe } from '@duncit/ai-monitoring/mui';

sx={{ ...aiMotion(`${aiBreathe} 1800ms ease-in-out infinite`) }}
```
