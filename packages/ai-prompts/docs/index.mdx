## Why this exists

Every AI feature on Duncit — pod and product moderation, the upload scan, the support chatbot,
the CRM parsers, the admin assistant, Ask Bot, the Agent, the release-notes writer — sends the
model a prompt that is stored in the database and read back **on every call**. Editing a prompt
in the AI portal changes what the product sends. There is no deploy in between.

That is a strong promise, and for a while it was only half true. The *system* turn came from the
library; the *user* turn — `Review this pod:\n…`, `Admin question: …` — was a template literal at
the call site, and the model an operator picked in the portal was ignored because the call site
pinned its own. So an operator changed a prompt, watched nothing happen, and reasonably concluded
the library did not work. Both halves come from the library now, and so does the model.

## The two kinds

|                          | **CODE** ("Code Inside Prompt")                          | **AI**                                    |
| ------------------------ | -------------------------------------------------------- | ----------------------------------------- |
| Where it comes from      | `server/src/modules/ai/prompt/catalog/`, seeded on boot   | Written in the AI portal                  |
| Who reads it             | A call site, on every request                             | Whatever fetches the public GET feed      |
| Create / delete in portal| No — a row nothing calls is not a feature                 | Yes                                       |
| Editable                 | Body, note, target model                                  | Everything                                |
| Reset                    | Yes, back to the catalogue text                           | No default to go back to                  |

A CODE prompt also carries two things the portal shows read-only, because the operator cannot
change them and needs them to edit safely: `usage` (which file sends it, on which surface, after
what) and `variables` (each `{{placeholder}}`, what the call site puts there, and an example).

## `{{ var }}`

Placeholders are `{{name}}`. Two rules, and both matter:

- **An unsupplied placeholder is left as written, not blanked.** Some bodies talk about
  `{{variables}}` as literal text — the MJML writer does — and swallowing those rewrites the
  instruction.
- **A required placeholder cannot be removed.** A body that lost `{{navigation_map}}` still runs,
  still costs money, and answers from nothing, with no error anywhere. The editor refuses the save
  and the server refuses it again.

```ts
import { renderPrompt, missingRequiredVariables, exampleValues } from '@duncit/ai-prompts';

renderPrompt('Review this pod:\n{{pod_fields}}', { pod_fields: 'Title: Chess' });
// → 'Review this pod:\nTitle: Chess'

renderPrompt('Preserve useful {{variables}} from existing MJML.', {});
// → unchanged: nothing was supplied for it, so it stays literal

missingRequiredVariables('You are the navigation bot.', prompt.variables);
// → ['navigation_map']

renderPrompt(prompt.content, exampleValues(prompt.variables)); // what the preview shows
```

The server keeps its own eight-line copy of these in `prompt.render.ts` — it imports no
`@duncit/*` package by design (rule 40), because everything it imports has to be COPYied into the
Docker image. The two are pinned to the same semantics by the tests on both sides.

## The page

The AI portal renders the whole library in one component:

```tsx
import { PromptLibraryView } from '@duncit/ai-prompts/mui';
import { apiOriginFromGraphqlUrl } from '@duncit/ai-prompts';

<PromptLibraryView apiOrigin={apiOriginFromGraphqlUrl(urlConfigs.graphqlUrl)} />;
```

`apiOrigin` is the only thing a surface must supply: the feed is served by the same process as
GraphQL, so it is derived from the endpoint the portal already talks to rather than a second env
var to get wrong between environments.

### Opening one prompt: the detail view

Clicking a row, a row menu's **Open details**, or a link (`/library?prompt=<key>`, which the AI
Features table builds with `libraryPromptPath`) opens that prompt's **detail view**. The page keeps
the open prompt in its URL, so the view survives a reload and can be sent to a colleague:

```tsx
const [params, setParams] = useSearchParams();

<PromptLibraryView
  apiOrigin={apiOrigin}
  openPromptKey={params.get('prompt')}
  onPromptOpen={(key, tab) => setParams((p) => { p.set('prompt', key); tab ? p.set(DETAIL_TAB_PARAM, tab) : p.delete(DETAIL_TAB_PARAM); return p; }, { replace: true })}
  onPromptClose={() => setParams((p) => { p.delete('prompt'); p.delete(DETAIL_TAB_PARAM); return p; }, { replace: true })}
/>;
```

Without `onPromptOpen` the view opens the details itself. The key is looked up across both kinds
and the archive (`useOpenPromptByKey`), and only an exact key match opens; an unknown key shows an
error rather than opening a neighbour the search also found.

The detail view's tabs (URL param `promptTab`):

- **Overview** — the complete prompt with Copy, its estimated token count, hits, model, category,
  and (code prompts) where it runs, its variables and a rendered preview.
- **Quality score** — ChatGPT's review (`scoreAiPrompt`, rubric = the `library.prompt_quality` code
  prompt): a score out of 100, strengths and improvements. Asked for automatically when the current
  body has none; stored with a hash of the body, so a prompt costs one review per version.
  **Rescore** asks again; a review of an older body is flagged stale.
- **History** — every saved version, newest first, as a full snapshot with who changed what.
  **Restore** copies an older version back as a new version.
- **Analytics** — hits, unique visitors, hits per day, and breakdowns by interaction, LLM, source
  (utm_source, else referrer host) and device, over 7/30/90/365 days.
- **Share** — the public link, the library link, and the LLM hand-off.

### Row menu, Quick view and the Archived tab

Each row has a menu: Open details, Edit, Quick view, Copy library link, Public share (opens the
Share tab), plus Reset (code), Archive and Delete (AI). **Quick view** shows the text and its size
without leaving the list. Archiving an AI prompt moves it to the **Archived** tab: it leaves the
other tabs, the public GET feed and its public link, keeps its history, and can be restored. Code
prompts cannot be archived — a call site reads them.

### Public share and the LLM hand-off

Turning on a prompt's public link gives `https://ai.duncit.com/p/<token>` (`publicShareUrl`), a page
that needs no login (`PublicPromptView`, mounted by the AI portal outside its auth wrapper). A visitor
fills in the placeholders (RHF + Zod, `publicPromptSchema`), adds their own input, sees the composed
prompt (`composePrompt`) and copies it or opens it in Claude, ChatGPT, Grok or Perplexity
(`PlatformSend`, `platformLink`). A prompt too long for a URL is copied first and the chat opened
empty. **Copy-ready scripts** (`injectionScript`, `bookmarklet`) type the prompt into an open chat;
they never press send, and the prompt is embedded as JSON so no text can escape the string.

The link is the gate: switching it off, archiving or deactivating the prompt makes it answer "not
available", exactly like a token that never existed. **New link** kills the old one.

### What is counted

Views, quick views, copies, link copies and LLM hand-offs in the portal (`recordAiPromptEvent`),
public page visits, copies and hand-offs (`POST /ai-prompts/share/:token/events`), and single-prompt
GET feed reads. A public visitor is a random id their browser made up — never an IP or an account —
and a referrer is kept as its host only.

### Edited code prompts

`AiPrompt.matches_default` is `false` when a code prompt's live body differs from its catalogue
default. That happens when someone edited it here, or when the default changed after the row was
seeded (the boot seed never writes over an existing body). The table marks those rows **Edited**,
and **Reset** brings them back to the default. It is `null` for AI prompts, which have no default.

## The public GET feed

```
GET /ai-prompts/prompts.json                      every active prompt
GET /ai-prompts/prompts.json?kind=AI              one kind
GET /ai-prompts/prompt.json?key=moderation.pod    one prompt
GET /ai-prompts/prompt.json?key=x&vars[city]=Pune already filled in
```

**No login and no key.** That is a deliberate product decision, and it is worth naming what it
trades away: anyone with the URL can read every active prompt, CODE ones included — and those are
the product's own instructions to the model, `moderation.pod` among them, which names the evasion
patterns it screens for. Treat everything reachable there as public writing. Deactivating a prompt
takes it off the feed, and so does archiving it; the feed never serves `usage` or `created_by`.

## What this package will not do

It does not send anything to a model, and it holds no OpenAI client. The library is what a prompt
*is*; `server/src/services/openai/openai.client.ts` is the one place the product talks to OpenAI.
