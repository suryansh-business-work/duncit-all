## Why this exists

Five websites drew the same logo five ways. `main-website` had a component with a
wordmark fallback; `ads-website`, `earnwith-website` and `partners-website` each inlined
an `<img>` with `|| '/duncit-logo.svg'` behind it; every one of them picked its own
height. So the same admin-uploaded logo rendered at a different size on every domain, and
the "no logo uploaded yet" state existed on exactly one of them.

## Use it

```astro
---
import BrandLogo from '@duncit/brand/BrandLogo.astro';
import FooterLogo from '@duncit/brand/FooterLogo.astro';
import { fetchBranding } from '../lib/site-data';

const branding = await fetchBranding();
---

<BrandLogo src={branding.website_header_logo_url} name={branding.app_name} height={56} />

<FooterLogo
  footerSrc={branding.website_footer_logo_url}
  headerSrc={branding.website_header_logo_url}
  name={branding.app_name}
/>
```

### The footer blocks

```astro
---
import NewsletterSignup from '@duncit/brand/NewsletterSignup.astro';
import PolicyStrip from '@duncit/brand/PolicyStrip.astro';
import SocialLinks from '@duncit/brand/SocialLinks.astro';
---

<NewsletterSignup graphqlUrl={graphqlUrl} source="ADS_WEBSITE_FOOTER" variant="card" />
<SocialLinks class="mt-5" />
<PolicyStrip policies={policies} baseUrl={mainSiteUrl} />
```

`NewsletterSignup` renders as a bordered card by default and as a footer row with
`variant="inline"`. Pass `consent` to require a ticked box before the address is sent.
`PolicyStrip` renders every policy on one wrapping row separated by pipes, and nothing at
all when the list is empty — a build that could not reach the API shows no empty heading.
`SocialLinks` defaults to Duncit's own accounts, so no site has to carry the handles.

### The mobile menu

```astro
---
import SiteMenu from '@duncit/brand/SiteMenu.astro';
---

<SiteMenu links={nav.links} actions={[nav.signup, nav.login]} />
```

The satellite sites hid their navigation below `lg` and put nothing in its place, so on a
phone the header was a logo and one button and every other link was unreachable. This is
the hamburger and the drawer it opens; it hides itself at `1024px`, which is the width the
headers reveal their inline links at — so the actions passed here are the sign-in and
sign-up the bar itself drops on a phone, not a second copy of buttons still rendered beside
the burger.

`onDark` paints the button white for a header that sits over a banner. Pass it ONLY when
that header is _always_ over one, as the partner site's is: it is decided at build time, so
a header that turns solid on scroll keeps a white burger on a cream bar — invisible. Such a
header leaves the prop off and paints `.site-menu-button` from its own scrolled state
instead.

## Everything here is plain CSS, not Tailwind

This package sits OUTSIDE every site's Tailwind source scan. A `flex gap-x-6` written in
here compiles to nothing, and the first version of `PolicyStrip` shipped exactly that: the
policy links rendered with no spacing at all, running into each other. The components style
themselves and borrow only the palette tokens, which every site declares:

```css
var(--color-line)   var(--color-ink)     var(--color-ink-soft)
var(--color-primary) var(--color-surface) var(--font-head)
var(--color-on-primary)
```

Each has a literal fallback, so a site that has not declared one still renders.

## There is no fetch in here

Every site already fetches branding at build time for its favicon and its footer. A
component that fetched again would double each page's build-time requests for a value the
caller is already holding. So the caller passes the URL, and this package owns only how
the mark is DRAWN.

The exceptions are `ReelSlider` and the CMS widgets, which read live data in the browser
at visit time on purpose — see their sections below.

## API

### `BrandLogo.astro`

| Prop | Type | Default | Meaning |
| --- | --- | --- | --- |
| `src` | `string \| null` | `null` | The admin's logo. Empty renders the wordmark. |
| `name` | `string` | `'Duncit'` | Alt text and the accessible name. |
| `height` | `number` | `56` | Rendered height in px; the wordmark scales off it. |
| `href` | `string \| null` | `'/'` | `null` renders a plain image instead of a link. |
| `loading` | `'eager' \| 'lazy'` | `'eager'` | The header mark is above the fold. |

### `FooterLogo.astro`

Takes `footerSrc` and `headerSrc` and applies the footer's own rule: the footer logo, then
the header logo, then the wordmark. Defaults to `height={96}` and `lazy`.

| Prop | Type | Default |
| --- | --- | --- |
| `footerSrc` | `string \| null` | `null` |
| `headerSrc` | `string \| null` | `null` |
| `name` | `string` | `'Duncit'` |
| `height` | `number` | `96` |
| `href` | `string \| null` | `'/'` |

### `SiteMeta.astro` and `site-meta`

Every website page's link-preview card. Before this the sites shipped a `<title>` and a
`<meta name="description">` and nothing else, so a duncit.com link posted into WhatsApp
or Slack unfurled with no picture — and on a page whose content arrives from the API
(a blog post, a short link) under the wrong title entirely.

```astro
---
import SiteMeta from '@duncit/brand/SiteMeta.astro';
import { fetchBranding } from '../lib/site-data';
import { urlConfigs } from '../config/url-configs';

const branding = await fetchBranding();
---

<SiteMeta
  title="Careers at Duncit"
  description="Build the friendship platform that matches people by energy."
  url={`${urlConfigs.siteUrl}${Astro.url.pathname}`}
  siteName={branding.app_name}
  imageUrl={branding.website_header_logo_url || null}
/>
```

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `title` | `string` | — | The page's own title; ` \| <siteName>` is appended unless the title already names the site. |
| `description` | `string` | — | One plain line. |
| `url` | `string` | — | The page's absolute address — `og:url` and `canonical`. |
| `siteName` | `string` | — | `og:site_name`. |
| `imageUrl` | `string \| null` | `null` | The card picture. |
| `largeImage` | `boolean` | `false` | True only when the picture is the page's own, not the logo standing in. |
| `type` | `'website' \| 'article'` | `'website'` | `article` for a blog post. |
| `socialTitle` / `socialDescription` | `string` | the title / description | The share card's own copy (`og:*` and `twitter:*`) when it should differ from the search title. |
| `twitterCard` | `'summary' \| 'summary_large_image'` | from `largeImage` | Forces the X card type. |

The component writes the tags between `<!-- meta:start -->` and `<!-- meta:end -->`
markers, and `site-meta` exports the same builder as a plain function
(`buildSiteMetaTags`, `injectSiteMeta`, `META_START`, `META_END`). That is what lets the
sites' HTML server recompose the block per request for the pages whose card is not
knowable at build time — one builder, so a card cannot drift from the page it describes.

### `GoogleAnalytics.astro`

The Google Analytics (gtag.js) tag, rendered in each site's `<head>` right after the
viewport meta, where Google asks for it.

```astro
---
import GoogleAnalytics from '@duncit/brand/GoogleAnalytics.astro';
---

<GoogleAnalytics site="MAIN" graphqlUrl={urlConfigs.graphqlUrl} />
```

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `site` | `TrackedWebsite` | — | `MAIN`, `PARTNERS`, `ADS`, `EARNWITH`, `STATUS` or `ECOMM` — which website this is. |
| `graphqlUrl` | `string` | — | The API the page asks for its tag. |

No id is baked into the build. Which GA4 tag each website loads — and whether it loads
one — is set per website in **Tech → Google Analytics**, and the page asks the public
`googleAnalyticsTag(site)` query as it opens. A change there reaches the website within
the API's cache TTL (a minute), with no redeploy. Staging and local stacks read their own
databases, so their traffic never lands in the production property unless someone sets
a tag there on purpose. `gtag` ends up on `window`, so a page can send its own events
with `gtag('event', …)`.

### `google-analytics`

The same loader as a plain module, for the React websites that cannot render an
`.astro` component (the status page and the pet store call it from their entry module).

```ts
import { loadGoogleAnalytics } from '@duncit/brand/google-analytics';

loadGoogleAnalytics(`${SERVER_BASE}/graphql`, 'STATUS');
```

| Export | Signature | Notes |
| --- | --- | --- |
| `loadGoogleAnalytics` | `(graphqlUrl: string, site: TrackedWebsite) => void` | Fire-and-forget: a page never waits on it, and a failure is logged, not shown. |
| `TrackedWebsite` | `'MAIN' \| 'PARTNERS' \| 'ADS' \| 'EARNWITH' \| 'STATUS' \| 'ECOMM'` | Mirrors the server's `TrackedWebsite` enum. |

**GA waits for consent.** Nothing of gtag.js is requested until the visitor has allowed
`analytics` on the consent banner (`whenWebConsentAllows` from `@duncit/utils`). A visitor
who allows it later gets the tag at that moment, without a reload; one who never answers
never loads it.

### `ConsentBanner.astro` and `consent-banner`

The tracking-consent banner (GDPR / ePrivacy), one implementation for all six websites.
The Astro sites render the component in `<head>` beside `GoogleAnalytics`; the two React
sites call `mountConsentBanner` from their entry module.

```astro
---
import ConsentBanner from '@duncit/brand/ConsentBanner.astro';
---

<ConsentBanner policyUrl="/policies" t={t} />
```

```ts
import { consentBannerCopy, mountConsentBanner } from '@duncit/brand/consent-banner';
import { siteT } from '@duncit/brand/site-i18n';

mountConsentBanner(consentBannerCopy(siteT), { policyUrl: `${MAIN_SITE_URL}/policies` });
```

| Export | Signature | Notes |
| --- | --- | --- |
| `ConsentBanner.astro` | `{ policyUrl: string; t?: SiteTranslate }` | Copy resolved at build time from `privacy.*`. |
| `mountConsentBanner` | `(copy, { policyUrl }, doc?) => void` | Shows itself while the browser has no answer, and again on any `[data-consent-open]` click. |
| `consentBannerCopy` | `(t) => ConsentBannerCopy` | Every line through the site's translator. |
| `CONSENT_BANNER_KEYS` | `Record<keyof ConsentBannerCopy, string>` | The `privacy.*` key behind each line. |

What makes the consent valid, and must not be designed away: the optional boxes start
unticked, "Reject all" is a first-level button as prominent as "Accept all", and
`PolicyStrip` carries a "Privacy choices" button (`data-consent-open`) on every page, so
withdrawing is as easy as agreeing. The answer is the shared `.duncit.com` cookie from
`@duncit/utils`, so it covers mWeb and every other subdomain too. Withdrawing analytics also
deletes GA's `_ga*` cookies.

### `EarnShowcase.astro`

The "Earn with Duncit" section: a wall of portraits — hosts, venue owners, shopkeepers and
sellers from India, the US, Africa, East Asia, Latin America and Europe — drifting gently,
with one CTA to earnwith.duncit.com. On every site's home page except earnwith's own.

```astro
---
import EarnShowcase from '@duncit/brand/EarnShowcase.astro';
---

<EarnShowcase href={urlConfigs.earnwithUrl} t={t} />
```

| Prop | Type | Meaning |
| --- | --- | --- |
| `href` | `string` | earnwith for this environment (`PUBLIC_EARNWITH_URL`), never a literal. |
| `t` | `SiteTranslate` | The site's build-time translator (`website.brand.earnShowcase.*`). |
| `eyebrow` / `heading` / `headingMuted` / `text` / `cta` | `string` | The section's words, set per page in the Website CMS; each one omitted renders the shipped copy. |
| `id` / `class` | `string` | Anchor id (default `earn-with-duncit`) and extra classes for the section. |

The photos live in `earn-showcase.ts` (`EARN_SHOWCASE_COLUMNS`), served from the Pexels CDN;
`earnShowcaseImage(url, width)` asks it for a cropped, compressed 4:5 tile at 1x and 2x. Nine columns on desktop, seven on tablet, five on a
phone. The wall is decoration (`aria-hidden`), the CTA is the one link, tiles tilt on hover,
the wall leans toward a fine pointer (`earn-showcase-dom.ts`), and reduced-motion visitors
get a still wall.

### `ReelSlider.astro` and `reel-slider`

The home-page Reel Slider: a 3D coverflow of the reels the Website portal manages
(**Website portal > Reel Slider**, one tab per site). Every site mounts it right under its
footer.

```astro
---
import ReelSlider from '@duncit/brand/ReelSlider.astro';
---

<ReelSlider graphqlUrl={urlConfigs.graphqlUrl} site="MAIN" t={t} />
```

| Prop | Type | Meaning |
| --- | --- | --- |
| `graphqlUrl` | `string` | Where `publicWebsiteReels` is read from. |
| `site` | `'MAIN' \| 'PARTNERS' \| 'ADS' \| 'EARNWITH'` | Whose reels to show. |
| `t` | `SiteTranslate` | The site's build-time translator (`website.brand.reels.*`). |

**This is the one component that reads at visit time, not build time.** A reel edit should
not wait for a deploy, so the bundled script asks `publicWebsiteReels` when the page opens
(a cached, public query). The section ships `hidden` and stays hidden when a site has no
reels or the API does not answer.

What it guarantees: every visible reel plays muted and looping; at most ONE reel has sound —
turning one on mutes the rest, and the sound follows the visitor to the next reel; nothing
plays while the section is off screen or the tab is hidden; reduced-motion visitors get
posters until they press play. Reels more than two places from the centre are not loaded at
all (`preload="none"`, no `src`), so ten reels never means ten downloads.

The limits live in **Website portal > Reel Slider Settings**: max reel size (checked in the
browser before an upload starts, default 20 MB) and max reels per site (default 10, enforced
by the server on every write and again on the public read).

| Export (`reel-slider`) | Signature | Notes |
| --- | --- | --- |
| `fetchSiteReels` | `(graphqlUrl, site) => Promise<SiteReel[]>` | Never rejects; a failure logs and answers `[]`. |
| `slideOffset` | `(index, active, total) => number` | Signed distance from centre on a circular track. |
| `wrapIndex` | `(active, delta, total) => number` | Steps around the circle. |
| `reelPoster` | `(videoUrl) => string` | ImageKit's `ik-thumbnail.jpg` still for a hosted video. |
| `reelSliderCopy` / `REEL_SLIDER_KEYS` | `(t) => ReelSliderCopy` | Control labels through the site's translator. |

The slides are built by script, so the component's CSS is `is:global` and every class is
prefixed `reel-` — Astro's scoped styles never reach a node created at runtime.

## CMS widgets & block markers

A page moved into the Website CMS is an HTML snapshot of the built page. The markup
survives that move; the client-side **behaviour** Astro bundled does not. So every
interactive widget's behaviour lives here as a framework-free module, and the legacy
sites mount the very same module — one implementation, whichever renderer drew the HTML.

### Widgets

Each widget root carries `data-cms-widget="<name>"`. Its module exports
`mount(root: HTMLElement): void`, reads **everything** from data attributes under that
root (never from Astro props, `import.meta.env` or a site config), and is idempotent: it
marks the root `data-cms-mounted` and returns early on a root already mounted.

```ts
// Mount only what this page contains.
import { WIDGET_LOADERS } from '@duncit/brand/widgets';

for (const root of document.querySelectorAll<HTMLElement>('[data-cms-widget]')) {
  void WIDGET_LOADERS[root.dataset.cmsWidget ?? '']?.().then((widget) => widget.mount(root));
}
```

```astro
<!-- A legacy page mounts one widget directly. -->
<script>
  import { mount } from '@duncit/brand/widgets/contact-form';

  for (const root of document.querySelectorAll<HTMLElement>('[data-cms-widget="contact-form"]')) mount(root);
</script>
```

JSON attributes (`data-copy`, `data-config`) are rendered by Astro, which escapes them.
Every string a widget shows comes from them — the modules carry no copy.

### Block markers

The shared components below put `data-cms-block="<key>"` and `data-cms-props` on their
root: the JSON of the props the page passed (minus `t`, `graphqlUrl` and any function),
so a migration can swap the snapshot back for the live block. `cmsBlockProps` (from
`@duncit/brand/cms-block`) builds it, and `CMS_BLOCKS` maps each key to its component.

| Key | Component | `data-cms-props` |
|---|---|---|
| `newsletter` | `NewsletterSignup.astro` | `{ source, heading?, text?, placeholder?, button?, variant?, consent?, consentLinkLabel?, consentLinkHref?, captcha?, busyText?, okText?, errorText?, class? }` |
| `reel-slider` | `ReelSlider.astro` | `{ site, eyebrow?, heading?, class? }` |
| `earn-showcase` | `EarnShowcase.astro` | `{ href, eyebrow?, heading?, headingMuted?, text?, cta?, id?, class? }` |
| `app-download` | `AppDownload.astro` | `{ eyebrow?, heading, headingAccent?, text?, perks?, stores: { icon, eyebrow, name, url? }[], soonLabel?, screenshot?, id?, class? }` |

| `policy-strip` | `PolicyStrip.astro` (only when it has policies) | `{ policies: { slug, title }[], baseUrl?, heading?, allLabel?, class? }` |

A prop the page did not pass is absent, and the component's default applies on redraw.

### Careers Apply (`CareersApply.astro`, `ApplyButton.astro`)

A careers opening's "Apply now" and the dialog it opens, for any site. Render
`CareersApply` once per page and an `ApplyButton` per role; the `careers-apply` widget
wires them. The CMS renderer draws both from the `apply` block the server puts on every
Careers card and career page.

```astro
---
import CareersApply from '@duncit/brand/CareersApply.astro';
import ApplyButton from '@duncit/brand/ApplyButton.astro';
import { PHONE_INTL_PLUS } from '@duncit/regex';
---
<ApplyButton role="QA Tester" roleId={entry.id} t={t} />
<CareersApply graphqlUrl={graphqlUrl} phonePattern={PHONE_INTL_PLUS.source.slice(1, -1)} t={t} />
```

`phonePattern` is the field's HTML `pattern`; pass it from `@duncit/regex` (the server's
own rule) — this package keeps no regex of its own.

### Design system CSS (`cms-design`)

Each CMS website has its own design system — tokens and fonts edited in the Website
portal's Design tab. `@duncit/brand/cms-design` turns that data into CSS, so the renderer
(`website/cms-site`) and the portal's editor canvas and previews draw a page identically.
Pure functions: no DOM, no fetch.

| Export | Returns |
|---|---|
| `tokensCss(tokens)` | One `:root{…}` rule of `--name:value` pairs, or `''` when there are none |
| `googleFontsHref(fonts)` | One Google Fonts css2 URL for every `GOOGLE` font (weights + italics), or `null` |
| `fontStack(font)` | A CSS `font-family` value: the quoted family, then its fallback (`sans-serif` when blank) |
| `fontCss(fonts)` | `@font-face` for every uploaded file, plus the role variables (`--font-heading`, `--font-body`, `--font-accent`) and any extra token a font is bound to |
| `designVariables(tokens, fonts)` | Every CSS variable the design declares as `{ name, value }[]` — tokens, then font variables (which win on a clash, as in the stylesheet). The Website portal lists these beside every SCSS editor |

```ts
import { fontCss, googleFontsHref, tokensCss } from '@duncit/brand/cms-design';

const href = googleFontsHref(site.design.fonts); // a <link rel="stylesheet"> when not null
const css = tokensCss(site.design.tokens) + fontCss(site.design.fonts);
```

## The wordmark is plain CSS on purpose

Its red is written as a literal rather than a Tailwind token. Five sites consume this and
none of them can be assumed to have declared the same token names — a `bg-primary` here
would render as nothing on a site whose theme calls it something else.

## Adding it to a site

It is an Astro component package, so the consuming site needs the dependency AND — for
anything built in Docker — the `COPY packages/brand …` lines in that site's Dockerfile.
Without them the build passes locally and fails only in deploy.
