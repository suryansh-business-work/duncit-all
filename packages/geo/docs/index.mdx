## Why this exists

The account-edit form exists twice — `app/mweb/src/pages/account-page/account-edit/LocationSelect.tsx`
and `app/mobile-app/src/forms/account-edit/LocationSelect.tsx` — and rule 27 says the two must
render the same options. A country list embedded in each file is two lists: one gets a country
added, the other does not, and a profile saved on the app stops being editable on mWeb.

The data itself is generated, not typed by hand. `scripts/gen-data.mjs` reads
`country-region-data` (a **devDependency**, so it never reaches an app bundle) and writes
`src/data.ts` as flat tuples. The package therefore ships zero runtime dependencies: Metro,
Vite and `tsc` each resolve `./src/index.ts` directly, with no build step and no Dockerfile
change.

## Use it

From mWeb's `LocationSelect` — Country drives State, City stays free text:

```ts
import { COUNTRY_OPTIONS, findCountryByName, getStatesForCountry } from '@duncit/geo';

const countryNames = useMemo(
  () => withCurrent(COUNTRY_OPTIONS.map((c) => c.name), country),
  [country],
);

const stateNames = useMemo(
  () =>
    withCurrent(
      getStatesForCountry(findCountryByName(country)?.isoCode).map((s) => s.name),
      state,
    ),
  [country, state],
);
```

`findCountryByName` is the bridge that makes this work: the profile document stores the country
**name**, not the ISO code, while `getStatesForCountry` keys off the code. Skipping the lookup
and passing the name straight through silently yields an empty state list.

## Sample data

The package ships the data — you do not supply it. What a consumer holds is the profile /
address row it is populating, which stores **names**, not codes:

```ts
/** A saved shipping address, exactly as the profile stores it. */
const address = {
  line1: 'Flat 1204, Sea Breeze Apartments',
  line2: 'Carter Road',
  city: 'Mumbai',
  state: 'Maharashtra',      // the state NAME
  country: 'India',          // the country NAME — this is what you look up
  pincode: '400050',
};
```

## Worked examples

Real values, read straight out of the shipped dataset.

```ts
COUNTRY_OPTIONS.length          // 249

COUNTRY_OPTIONS.slice(0, 5)
// [
//   { name: 'India',          isoCode: 'IN', flag: '🇮🇳' },   ← pinned first
//   { name: 'Afghanistan',    isoCode: 'AF', flag: '🇦🇫' },
//   { name: 'Åland Islands',  isoCode: 'AX', flag: '🇦🇽' },
//   { name: 'Albania',        isoCode: 'AL', flag: '🇦🇱' },
//   { name: 'Algeria',        isoCode: 'DZ', flag: '🇩🇿' },
// ]
```

India sits at index 0 and the remaining 248 are alphabetical — `Åland Islands` sorting
between Afghanistan and Albania is `localeCompare`, not a bug.

Resolving the saved address:

```ts
findCountryByName(address.country)
// { name: 'India', isoCode: 'IN', flag: '🇮🇳' }

findCountryByName('United Arab Emirates')
// { name: 'United Arab Emirates', isoCode: 'AE', flag: '🇦🇪' }

findCountryByName('Wakanda')     // undefined
findCountryByName(undefined)     // undefined
```

Then the dependent state select:

```ts
const states = getStatesForCountry(findCountryByName(address.country)?.isoCode);

states.length                    // 36
states.slice(0, 4)
// [
//   { name: 'Andaman and Nicobar Islands', isoCode: 'AN', countryCode: 'IN' },
//   { name: 'Andhra Pradesh',              isoCode: 'AP', countryCode: 'IN' },
//   { name: 'Arunachal Pradesh',           isoCode: 'AR', countryCode: 'IN' },
//   { name: 'Assam',                       isoCode: 'AS', countryCode: 'IN' },
// ]

states.find((s) => s.name === address.state)
// { name: 'Maharashtra', isoCode: 'MH', countryCode: 'IN' }

getStatesForCountry('US').length // 62 — includes DC and the territories
getStatesForCountry('SG').length // 5
getStatesForCountry('ZZ')        // []  unknown code
getStatesForCountry()            // []  nothing selected yet
```

`getStatesForCountry` returning `[]` rather than throwing is what lets a country select
render before anything is chosen, and lets a country with no sub-divisions simply hide the
state field:

```tsx
const states = getStatesForCountry(countryCode);
{states.length > 0 && (
  <TextField select label="State" value={state} onChange={onStateChange}>
    {states.map((s) => <MenuItem key={s.isoCode} value={s.name}>{s.name}</MenuItem>)}
  </TextField>
)}
```

## API

| Export | Type | Meaning |
| --- | --- | --- |
| `COUNTRY_OPTIONS` | `GeoCountry[]` | All 249 countries, India first then alphabetical. A module constant — built once at import. |
| `getStatesForCountry` | `(countryCode?: string) => GeoState[]` | States for an ISO alpha-2 code, alphabetical. `[]` when the code is unknown or omitted. |
| `findCountryByName` | `(name?: string) => GeoCountry \| undefined` | Exact-match name lookup — the profile stores names, not codes. |

| Type | Fields |
| --- | --- |
| `GeoCountry` | `name: string`, `isoCode: string` (ISO-3166 alpha-2), `flag: string` (emoji, derived from `isoCode`) |
| `GeoState` | `name: string`, `isoCode: string`, `countryCode: string` |

There are no options objects and no defaults beyond `countryCode` being optional. `name` is
the display value and the stored value; `isoCode` is what you pass back into
`getStatesForCountry`.

## No live preview

Plain data and three lookups — no component. A country/state pair renders through MUI
`TextField select` in the portals and Tamagui in native, so the markup belongs to the
consumer, not here.

## `@duncit/geo` vs `@duncit/location` — pick the right one

These are not alternatives and must not be swapped.

| | `@duncit/geo` | `@duncit/location` |
| --- | --- | --- |
| Source | bundled dataset, offline | admin-managed Location DB, over GraphQL |
| Depth | country → state | country → state → city → locality (+ pincode) |
| Free text | city is free text | none, every level is a strict dropdown |
| Used by | user profiles (mWeb + native) | venue/club/CRM forms in the portals |

A profile does not need to match an admin location row, so it uses the dataset. Anything that
has to line up with admin — a venue, a club, a pod's locality — must use `@duncit/location`,
otherwise the record cannot be matched to a locality later.

## The lists are already sorted — do not sort again

`COUNTRY_OPTIONS` is `localeCompare`-sorted with **India pinned first**, deliberately, for an
India-heavy user base. `getStatesForCountry` returns its states alphabetically. Re-sorting at a
call site throws the India pin away and makes the two surfaces differ.

`getStatesForCountry` returns `[]` for an unknown or `undefined` code rather than throwing — a
half-filled profile with no country yet is normal, not an error.

## Flags

`GeoCountry.flag` is an emoji built by mapping A–Z to regional-indicator code points, computed
once at module load. It is a plain string, so it renders in MUI and in Tamagui `Text` alike;
there is no icon asset and rule 39's fallback-icon bundle does not apply to it.

## Regenerating the dataset

```
node scripts/gen-data.mjs   # from packages/geo
```

Never hand-edit `src/data.ts` — it carries a do-not-edit header and the next regeneration
discards your change. Bump `country-region-data`, regenerate, and commit the diff.

## Coverage

`vitest.config.ts` sets 100/100/100/100 and deliberately does **not** apply the usual
`src/index.ts` barrel exclusion, because in this package the barrel *is* the logic —
`COUNTRY_OPTIONS`, `getStatesForCountry`, `findCountryByName` and `flagForIso` all live there.
Excluding it would report 100% while testing nothing.
