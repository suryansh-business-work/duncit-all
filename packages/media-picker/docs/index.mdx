## Why this exists

Every surface that lets a user attach an image had its own copy of the same three things: a
`<Dialog>` with device / Pexels-photo / Pexels-video tabs, an `uploadImage` mutation call, and a
size check. Eleven copies of the upload path means eleven places that keep a stale cap after
Admin > Upload Settings changes one.

The copies are now re-export shims — `app/mweb/src/components/MediaPickerDialog.tsx`,
`portals/admin/src/components/MediaPickerDialog.tsx`, `portals/marketing/...`,
`portals/onboarding/...` are all literally `export { default } from '@duncit/media-picker';`.
The GraphQL documents live here too (`UPLOAD_IMAGE`, `GET_IMAGEKIT_AUTH`, `UPLOAD_SETTINGS`), so
a portal never hand-rolls the upload mutation; `portals/admin/src/pages/upload-settings/queries.ts`
re-exports `UPLOAD_SETTINGS` rather than declaring it again.

## Use it

The ready-made field is the common case — it owns the file input, the preview, the ImageKit
upload and the error text. From `portals/crm/src/forms/fields/ImageUploadField.tsx`:

```tsx
import { SingleImageUploadField } from '@duncit/media-picker';

<SingleImageUploadField
  variant="avatar"
  label={label}
  value={field.value ?? ''}
  onChange={field.onChange}
  folder="crm"
  shape="square"
  maxBytes={8 * 1024 * 1024}
  oversizeMessage={() => 'Max 8MB. Compress and try again.'}
  fallbackMimeType="image/png"
  uploadTestId={`upload-${name}`}
/>
```

For a free-form pick (device, Pexels photo or Pexels video) render the dialog itself:

```tsx
import MediaPickerDialog from '@duncit/media-picker';

<MediaPickerDialog
  open={open}
  onClose={close}
  onPicked={(url) => form.setValue('image_url', url)}
  folder="/pods"
  surface="PORTALS"
/>
```

## `useUploadCaps(surface)` — the settings as the numbers a picker works in

`useUploadSettings` hands back the admin row; this turns it into byte caps and one
`validate`, which is the shape every call site was writing for itself:

```tsx
const caps = useUploadCaps('MWEB');

caps.maxImageBytes; // max_image_mb × 1 MB
caps.maxVideoBytes; // max_video_mb × 1 MB
caps.maxDocumentBytes; // the server's own document ceiling — not an admin setting
caps.validate(file, { allowImage: true, allowVideo: true, allowDocuments: false });
```

Reach for it instead of a `const MAX_BYTES` at the top of a file. That constant is how a
support form ended up judging a photo by a document ceiling, and how three surfaces
advertised caps the admin panel had not shown in a year. `SingleImageUploadField` and
`AttachmentUploadField` already call it: **omit `maxBytes` and the admin decides**, pass a
number to override, pass `null` to leave the gate to the server alone.

It is an enhancement, never a gate — until the query answers (and if it never does) the
package floor applies: 15 MB image, 100 MB video, 100 MB document.

## Worked examples

Real return values, from running the exports against that row.

`validateFile(file, policy, caps)` returns **`null` when the file is fine** and a message
otherwise — the message is what you show the user verbatim:

```ts
const imagesOnly = { allowImage: true, allowVideo: false, allowDocuments: false };
const anything  = { allowImage: true, allowVideo: true,  allowDocuments: true  };

validateFile(jpg2MB,   imagesOnly, portalCaps); // null
validateFile(jpg12MB,  imagesOnly, portalCaps); // 'Image is too large (max 8 MB)'
validateFile(heic1KB,  imagesOnly, portalCaps); // 'Image format not allowed (allowed: jpg, png, webp)'
validateFile(mp4_20MB, imagesOnly, portalCaps); // 'Please choose an image or video file'
validateFile(mp4_20MB, anything,   portalCaps); // null
validateFile(mp4_90MB, anything,   portalCaps); // 'Video is too large (max 60 MB)'
validateFile(mp4_90MB, anything);               // null  ← no caps = the static 100 MB fallback
validateFile(pdf4MB,   anything,   portalCaps); // null
validateFile(pdf4MB,   imagesOnly, portalCaps); // 'Please choose an image or video file'
```

The fourth line is the whole point of the `policy` argument: an `accept="image/*"` picker
rejects a video even though the video itself is legal — the old admin copy accepted it. And
the seventh line is the trap in "Upload Settings are admin data": with `caps` omitted (which
is what `useUploadSettings` returning `null` gives you) a 90 MB video passes the client check
and is then rejected by the server.

`describeAttachment(url)` — classification from the URL alone:

```ts
describeAttachment('https://ik.imagekit.io/duncit/pods/weekend-pottery-hero.JPEG?tr=w-400');
// { url: '…', name: 'weekend-pottery-hero.JPEG', ext: 'jpeg', kind: 'image' }
describeAttachment('https://ik.imagekit.io/duncit/pods/reels/pottery-reel.mp4');
// { url: '…', name: 'pottery-reel.mp4', ext: 'mp4', kind: 'video' }
describeAttachment('https://ik.imagekit.io/duncit/support/venue-agreement.pdf');
// { url: '…', name: 'venue-agreement.pdf', ext: 'pdf', kind: 'doc' }
describeAttachment('https://ik.imagekit.io/duncit/misc/no-extension');
// { url: '…', name: 'no-extension', ext: '', kind: 'doc' }   ← unknown falls back to doc
```

The query string is stripped before the basename is read, and `ext` is lowercased but **not**
rewritten — `.JPEG` reports `ext: 'jpeg'`. The `jpeg → jpg` normalisation is inside
`validateFile`'s format check, not here.

```ts
isVideoUpload('clip.mkv', '');           // true   ← browsers report no MIME for .mkv
isVideoUpload('clip.mp4', 'video/mp4');  // true
isVideoUpload('photo.jpg', 'image/jpeg');// false
typeLabel('pdf');                        // 'PDF'
typeLabel('');                           // 'FILE'
```

Crop helpers, against `portalUploadSettings.crop_presets`:

```ts
croppablePresets(presets).map((p) => p.key);
// ['RATIO_16_9', 'RATIO_1_1', 'POD_FEATURE']
// NO_CROP is 0×0 and STORY_9_16 is disabled — both drop out.

presetAspect({ key: 'RATIO_16_9',  width: 1920, height: 1080, … }); // 1.7777777777777777
presetAspect({ key: 'POD_FEATURE', width: 1080, height: 1350, … }); // 0.8
presetAspect({ key: 'NO_CROP',     width: 0,    height: 0,    … }); // 1  ← guarded, never a divide-by-zero

suggestPresetKey(4032, 3024, presets); // 'RATIO_1_1'    (4:3 source is closer to 1.0 than to 1.78)
suggestPresetKey(1080, 1920, presets); // 'POD_FEATURE'  (STORY_9_16 would be exact but is disabled)
suggestPresetKey(0, 0, presets);       // null           (unknown source size)

formatBytes(512);        // '512 B'
formatBytes(663552);     // '648 KB'
formatBytes(13002342);   // '12.4 MB'
formatDuration(9);       // '0:09'
formatDuration(75);      // '1:15'
formatDuration(0);       // ''
```

`pickBestVideoFile` picks HD first, then the widest at or under 1080p:

```ts
pickBestVideoFile({
  video_files: [
    { quality: 'sd', width: 640,  height: 360,  link: 'a.mp4' },
    { quality: 'hd', width: 1920, height: 1080, link: 'b.mp4' },
    { quality: 'hd', width: 3840, height: 2160, link: 'c.mp4' },
  ],
});
// { quality: 'hd', width: 1920, height: 1080, link: 'b.mp4' }   ← the 4K entry is skipped
```

## API reference

### `MediaPickerDialog` (also the default export)

| Prop | Type | Required | Default | Meaning |
| --- | --- | --- | --- | --- |
| `open` | `boolean` | yes | — | Dialog visibility. |
| `onClose` | `() => void` | yes | — | Close handler. |
| `onPicked` | `(url: string) => void` | yes | — | Fires with the final stored URL. |
| `folder` | `string` | no | — | ImageKit folder, e.g. `'/pods'`, `'/branding'`. |
| `title` | `string` | no | — | Dialog heading. |
| `accept` | `string` | no | images + videos | Comma-separated MIME list. |
| `allowDocuments` | `boolean` | no | derived from `accept` | Pass `false` to force-disable documents even for a pdf accept list. |
| `surface` | `'PORTALS' \| 'MOBILE' \| 'MWEB'` | no | — | Which Upload Settings row drives sizes, formats and crop presets. |
| `max` | `number` | no | `1` | How many images ONE open may return. `1` closes on the first pick; above 1 the picks collect in a tray. |
| `onPickedMany` | `(urls: string[]) => void` | no | — | Fires once with every picked URL. Required when `max` is above 1. |
| `seedQuery` | `string` | no | — | What to search Pexels for before the user types — e.g. the pod's sub-category. Seeds the photos AND the videos tab, so a reel picker opens on the category too. |
| `orientation` | `'landscape' \| 'portrait' \| 'square' \| ''` | no | `''` | Pexels orientation to start on. A cover is wide, so pass `'landscape'`. |
| `deviceOnly` | `boolean` | no | `false` | Hide the Pexels tabs and offer the device alone. For a picker whose answer has to be a real photograph of something that happened — a pod’s own media, which is what a host’s payout is evidenced on. A stock library is right for a cover and wrong there, so the tabs are absent rather than discouraged. |

#### Picking more than one

`max` is the number **this open** may return, not the field's total — a field
already holding three of five passes `max={2}`. Above one, the dialog stops
closing on a pick: both tabs keep working and the picks land in a numbered tray
(the first is the cover), so two Pexels photos and one of the user's own can be
chosen in a single visit. `onPicked` still fires per URL if you want to stream
them; `onPickedMany` fires once on **Use these N**.

The seat of it is small on purpose: the tabs are unchanged, and multi-pick works
by handing them a `onClose` that does nothing. `useMediaSelection` holds the tray
and defers the cap and de-duplication to `addToSelection` in `@duncit/utils`, so
the native app — which cannot import this MUI package — enforces the identical
rule with Tamagui components (rules 27 and 40).

```tsx
<MediaPickerDialog
  open={open}
  onClose={() => setOpen(false)}
  max={coverSlotsLeft(urls.length)}
  seedQuery={coverSearchTerm(subCategoryName)}
  orientation="landscape"
  onPicked={addUrl}
  onPickedMany={addUrls}
/>
```

## Live preview

No live preview on this page. Every component here needs an `ApolloProvider` — the dialog
reads Upload Settings, the fields call the upload mutation — and the docs-site preview islands
are static, dependency-free React with no client and no server. A preview that mocked the
Apollo client would be showing you a mock-up of an upload, which is worse than no preview: the
one thing a reader wants to see is whether the real cap rejects their file, and that is what
the `validateFile` examples above show with real return values.

The pure helpers (`validateFile`, `describeAttachment`, the crop utilities) are the part worth
previewing, and they have no UI.

## Two upload paths — pick the right one

| Export | Transport | Use for |
| --- | --- | --- |
| `useImagekitBase64Upload` / `uploadImageToImagekit` | base64 through the `uploadImage` server mutation | images, small files |
| `useImagekitDirectUpload` / `directUploadToImagekit` | signed auth from `getImagekitAuth`, then a direct XHR to ImageKit | videos, reels, anything large |

The base64 path is bounded by the API request-body limit and a 50 MB server-side video cap. Pod
reels and status videos exceed both, so `app/mweb/src/pages/create-pod-page/create-pod/fields/PodReelAccordion.tsx`
uses the direct path and gets real byte progress:

```tsx
const { upload, uploading } = useImagekitDirectUpload();
const rawUrl = await upload(file, '/pods/reels', setPct);
const url = await compressUploadedVideo(client, rawUrl, '/pods/reels', 'MWEB', setPct);
```

`compressUploadedVideo` runs **after** the raw upload — it takes the uploaded URL, not the `File`.

## Upload Settings are admin data, not constants

`validateFile` carries static fallbacks (15 MB image, 100 MB video, 50 MB document) but takes a
`FileCaps` override. `useUploadSettings(surface)` loads the admin-managed row for
`'PORTALS' | 'MOBILE' | 'MWEB'`; it returns `null` until the query resolves, and a component that
treats `null` as "no limits" will accept a file the server then rejects. Pass the caps down, or let
`SingleImageUploadField` / `MediaPickerDialog` do it — they already read the settings for the
`surface` you give them.

The query needs a signed-in caller, so gate it on whatever opens your dialog:
`useUploadSettings('MWEB', { skip: !open })`. A picker that sits mounted-but-closed for the whole
session otherwise asks on every page load, and a signed-out visitor's ask is refused and logged.

Crop presets come from the same row. Use `croppablePresets` to filter out the disabled ones and
`presetAspect` for the aspect ratio — a preset with `width: 0, height: 0` means *No Crop* and must
not be divided.

## MUI only — this package must never reach the native app

`@mui/material`, `@mui/icons-material`, `@apollo/client` and `react` are **peer** dependencies, and
`react-easy-crop` is a real dependency. The mobile app cannot import any of it; native media
picking is a separate Tamagui/Expo path. Nothing here is safe to put behind a shared "media" export
that both twins consume.

## Attachments vs images

`SingleImageUploadField` is images only. Documents (venue papers, pod bills) go through
`AttachmentUploadField` with `ATTACHMENT_ACCEPT_ALL`, as in
`app/mweb/src/pages/host-manage-page/pod-complete/BillUploadField.tsx`. To render an already-stored
attachment, use `AttachmentPreview`; to classify a bare URL first, `describeAttachment(url)` returns
the `image | video | doc` kind, display name and extension. Do not re-derive that from the URL
string at the call site — the extension normalisation (`jpeg` → `jpg`) lives in one place.

## Coverage gate

`vitest.config.ts` sets 100/100/100/100, but `coverage.include` is `['src/utils.ts']` only. The
gate is real for the pure validation logic; the MUI/Apollo dialog is covered by the portals'
Cypress flows instead. Adding a new pure helper to `src/utils.ts` therefore requires tests for
every branch, while adding one to a `.tsx` does not — an asymmetry worth knowing before you decide
where a helper goes.

## The AI Monitoring notice

Every field and dialog in this package renders `<AiMonitoringChip />` from
`@duncit/ai-monitoring/mui` beside its upload control. Do not add another one at
a call site, and do not remove it from a field: the chip is how a person finds
out — before they pick a file — that what they upload is screened by AI, and the
picker is the one place that promise can be made everywhere at once.

The wording it shows is edited in AI Portal → AI Monitoring → Settings; the
checks it describes are listed in AI Portal → AI Monitoring → Logs. The chip
needs no props and renders nothing when an operator turns the notice off.

## Which route an upload takes

Two, and both are logged:

- `uploadImageToImagekit` / `useImagekitBase64Upload` — the GraphQL mutation.
  Applies crop, compression and the per-surface size and format rules.
- `directUploadToImagekit` / `useImagekitDirectUpload` — a streamed multipart
  POST to the server's `/upload` route, which is what gets a large video past
  the API body limit. It carries no body limit of its own, so pass the
  `surface` argument: the raw POST holds only a one-shot ticket, and the surface
  fixed on that ticket is what the AI Monitoring row is attributed to.
