## Why this exists

Fifteen portals each had their own list page: a `<TextField>` search wired to a hand-rolled
debounce, a `<Table>` or a raw `<AgGridReact>`, a `<TablePagination>`, and a `useEffect` that
turned all of that into GraphQL variables. Every one of them had its own idea of what page 1
meant, its own sort-direction naming, and its own handling of "search changed, reset to page 1".

Rule 37 is the outcome: if a portal renders a table, it renders `DuncitTable`. One query state
shape (`TableQueryState`), one server contract (`TableQueryInput` via `tableQueryToGql`), one
place where a pagination bug gets fixed.

MUI owns the chrome — toolbar, progress bar, error `Alert`, `TablePagination`. AG Grid owns
only the rows.

## Use it

From `portals/finance/src/pages/finance/backout-refund-page/BackoutRefundTable.tsx`:

```tsx
import { DuncitTable, type DuncitColumn, type TableFetch } from '@duncit/table';

const columns: DuncitColumn<BackoutRefundRequest>[] = [
  { field: 'backout_no', headerName: 'Backout ID', cellRenderer: renderBackoutNo },
  {
    field: 'backout_status',
    headerName: 'Status',
    filter: { type: 'select', options: BACKOUT_STATUS_OPTIONS },
    cellRenderer: renderBackoutStatus,
  },
  { field: 'joined_at', headerName: 'Joined', hide: true, sortable: false, width: 170 },
  { field: 'actions', headerName: 'Actions', sortable: false, width: 110, cellRenderer: renderActions },
];

<DuncitTable<BackoutRefundRequest>
  tableId="finance-backout-refunds"
  columns={columns}
  fetchRows={fetchRows}
  getRowId={(row) => row.id}
  onRowClick={onRowClick}
  emptyText="No backout refund requests yet."
  searchPlaceholder="Search by Backout ID"
  defaultSort={{ field: 'created_at', dir: 'desc' }}
  refetchRef={refetchRef}
/>;
```

`fetchRows` is the only data path. Build it with the Apollo bridge rather than by hand:

```ts
import { useApolloTableFetch } from '@duncit/table';

const fetchRows = useApolloTableFetch<PodRow>(client, PODS_TABLE, 'podsTable', {
  extraFilters: clubId ? [{ field: 'club_id', op: 'eq', value: clubId }] : undefined,
}, [clubId]);
```

## Worked examples

Every output below was produced by running the export against the fixtures above.

`tableQueryToGql(payoutQuery)` — the exact `TableQueryInput` variables object. Note that it
**always emits both `value` and `values`**, filling the unused one with `null`, so the server
sees one stable shape:

```json
{
  "query": {
    "search": "aarav",
    "page": 2,
    "page_size": 25,
    "sort_by": "created_at",
    "sort_dir": "desc",
    "filters": [
      { "field": "payout_status", "op": "in",       "value": null,    "values": ["PENDING", "PAID"] },
      { "field": "amount",        "op": "between",  "value": null,    "values": ["500", "5000"] },
      { "field": "is_active",     "op": "is_true",  "value": null,    "values": null },
      { "field": "host_name",     "op": "contains", "value": "aarav", "values": null }
    ]
  }
}
```

An empty search is sent as `null`, not `''` (`search: q.search || null`).

`filterChipLabel(payoutColumns, filter)` — one chip per applied filter, labelled from the
column's `headerName`:

```ts
payoutQuery.filters.map((f) => filterChipLabel(payoutColumns, f));
// [
//   'Status: PENDING, PAID',
//   'Amount (₹): 500 – 5000',   ← en dash, from the `between` op
//   'Active: Yes',              ← is_true / is_false render as Yes / No
//   'Host contains aarav',
// ]
```

`formatDateCell` and `dateColumn()`:

```ts
formatDateCell('2026-07-28T09:15:00.000Z');                    // '28 Jul 2026'
formatDateCell('2026-07-28T09:15:00.000Z', 'dd/MM/yyyy HH:mm'); // '28/07/2026 14:45' (IST)
formatDateCell(null);                                           // '—'  (EM_DASH)
DEFAULT_DATE_FORMAT;                                            // 'd MMM yyyy'
```

`date-fns` formats in the **viewer's** timezone, which is why the second line reads 14:45 for
a 09:15 UTC timestamp on an IST machine. Never hand-roll this with `toLocaleDateString`
(rule 11).

```ts
dateColumn<PayoutRow>();
// {
//   field: 'created_at',
//   headerName: 'Created',
//   hide: true,
//   width: 130,
//   filter: { type: 'date' },
//   valueGetter: [Function],
// }

const col = dateColumn<PayoutRow>();
col.valueGetter({ created_at: '2026-07-28T09:15:00.000Z' }); // '28 Jul 2026'
col.valueGetter({ created_at: null });                       // '—'
```

`activeChipColumn()` returns both a chip renderer and a text `valueGetter`, so the column is
still sortable/exportable as words:

```ts
activeChipColumn<PayoutRow>();
// {
//   field: 'is_active',
//   headerName: 'Status',
//   width: 110,
//   filter: { type: 'boolean' },
//   cellRenderer: [Function],   ← <Chip size="small" color="success|default" />
//   valueGetter: [Function],
// }

col.valueGetter({ is_active: true });  // 'Active'
col.valueGetter({ is_active: false }); // 'Inactive'
```

`makeApolloTableFetch` with a pinned `extraFilters` — the pinned filter is **appended after**
the user's own filters and never becomes a chip:

```ts
const fetchRows = makeApolloTableFetch<PayoutRow>(client, PAYOUTS_TABLE, 'payoutsTable', {
  extraFilters: [{ field: 'club_id', op: 'eq', value: '652f1c3a9d4b2e0011ac77e1' }],
});

await fetchRows(payoutQuery);
// client.query called with fetchPolicy 'network-only' and variables:
//   query.filters = [ …the four filters above…,
//                     { field: 'club_id', op: 'eq', value: '652f1c3a9d4b2e0011ac77e1', values: null } ]
// returns { rows: [...], total: 137 }   ← unwrapped from data.payoutsTable
```

## API reference

### `DuncitTable<T>`

| Prop | Type | Required | Default | Meaning |
| --- | --- | --- | --- | --- |
| `tableId` | `string` | yes | — | Persistence namespace for column prefs + density. Never reuse one. |
| `columns` | `ReadonlyArray<DuncitColumn<T>>` | yes | — | Column definitions. |
| `fetchRows` | `TableFetch<T>` | yes | — | `(q: TableQueryState) => Promise<TablePage<T>>` — the only data path. |
| `getRowId` | `(row: T) => string` | yes | — | Stable row identity for AG Grid. |
| `onRowClick` | `(row: T) => void` | no | — | Row click handler. |
| `getRowStyle` | `(row: T) => RowStyle \| undefined` | no | — | Per-row inline style (e.g. tint a low-stock row). |
| `toolbarActions` | `ReactNode` | no | — | Right-aligned toolbar extras, e.g. a "+ Create" button. |
| `emptyText` | `string` | no | — | Empty-state copy. |
| `defaultSort` | `{ field: string; dir: 'asc' \| 'desc' }` | no | unsorted | Initial sort. |
| `defaultPageSize` | `10 \| 25 \| 50 \| 100` | no | `25` | Initial page size. |
| `searchPlaceholder` | `string` | no | — | Search box placeholder. |
| `refetchRef` | `MutableRefObject<(() => void) \| null>` | no | — | Filled with the table's `refetch` so a parent can reload after a mutation. |
| `externalFilters` | `ReadonlyArray<TableFilterValue>` | no | — | Page-driven filters (tab/URL/select). Compared by value, reset to page 1, **no chip**. |
| `selection` | `{ onChange: (rows: T[]) => void; clearRef?: MutableRefObject<(() => void) \| null> }` | no | — | Opt in to a checkbox column. Absent means no selection config reaches AG Grid at all. `onChange` gets the rows ticked **right now** (and `[]` when a page change wipes them); `clearRef` is filled with a fn that unticks the grid. See [Selection is per page, and it is a mirror](#selection-is-per-page-and-it-is-a-mirror). |

### Data types

| Type | Shape | Notes |
| --- | --- | --- |
| `TableQueryState` | `{ search: string; page: number; pageSize: number; sortBy: string \| null; sortDir: TableSortDir; filters: TableFilterValue[] }` | `page` is **1-based**; `search` is already debounced (400 ms) by the time `fetchRows` sees it. |
| `TableFilterValue` | `{ field: string; op: TableFilterOp; value?: string; values?: string[] }` | `values` carries `in` lists and `between` pairs; everything is stringified (ISO for dates). |
| `TableFilterOp` | `'eq' \| 'ne' \| 'in' \| 'contains' \| 'gte' \| 'lte' \| 'between' \| 'is_true' \| 'is_false'` | — |
| `TablePage<T>` | `{ rows: T[]; total: number }` | `total` drives `TablePagination`, so it must be the unpaged count. |
| `TableFetch<T>` | `(q: TableQueryState) => Promise<TablePage<T>>` | — |
| `DuncitColumn<T>` | `{ field; headerName; sortable?; filter?; width?; flex?; minWidth?; hide?; valueGetter?; cellRenderer? }` | `field` is both the server sort/filter key and the row accessor. `sortable` defaults to `true`; no `filter` means not filterable; `hide` hides by default but keeps it in the column menu. |
| `DuncitColumnFilter` | `{ type: 'text' } \| { type: 'select'; options; multiple? } \| { type: 'number' } \| { type: 'date' } \| { type: 'boolean' }` | `number` renders min/max → `gte`/`lte`/`between`; `date` renders from/to MUI X pickers → `between` with ISO values. |

### Hooks and helpers

| Export | Signature | Notes |
| --- | --- | --- |
| `useTableQuery` | `<T>({ fetchRows, defaultSort?, defaultPageSize?, externalFilters? }) => UseTableQueryResult<T>` | The state machine behind the table: `{ rows, total, loading, error, query, searchInput, setSearchInput, setPage, setPageSize, setSort, setFilters, refetch }`. A monotonic sequence guard drops stale responses. |
| `useTablePrefs` | `(tableId: string) => { hiddenOverrides: Record<string, boolean>; toggleColumn; resetColumns; density; toggleDensity }` | Reads/writes `localStorage`, every access wrapped in try/catch. Density defaults to `'standard'`. |

| `useApolloTableFetch` | `<Row>(client, query, resultKey, options?, deps?) => TableFetch<Row>` | The same thing memoized — **always** this one inside a component. |
| `TableGqlClient` | `{ query(options: { query: unknown; variables?: Record<string, unknown>; fetchPolicy?: string }): Promise<{ data: unknown }> }` | Structural, so the package needs no `@apollo/client` dependency. |
| `tableQueryToGql` | `(q: TableQueryState) => { query: {...} }` | The single client→server mapping. |
| `filterChipLabel` | `<T>(columns, filter: TableFilterValue) => string` | Falls back to `filter.field` when no column matches. |
| `dateColumn` | `<T>(options?: DateColumnOptions<T>) => DuncitColumn<T>` | Defaults: `field 'created_at'`, `headerName 'Created'`, `hide true`, `width 130`, `filterable true`, `format 'd MMM yyyy'`. `formatDate` wins over `format`. |
| `activeChipColumn` | `<T>(options?: ActiveChipColumnOptions<T>) => DuncitColumn<T>` | Defaults: `field 'is_active'`, `headerName 'Status'`, `width 110`, labels `Active`/`Inactive`, `filterable true`. |

| `formatDateCell` | `(iso: string \| null \| undefined, dateFormat?: string) => string` | `EM_DASH` when empty. |
| `buildAgTheme` | `(muiTheme: Theme, density: 'compact' \| 'standard')` | Maps the live MUI theme onto AG Grid's Theming API — zero CSS imports, light and dark both work. |
| `DEFAULT_DATE_FORMAT` / `EM_DASH` | `'d MMM yyyy'` / `'—'` | The shared date pattern and empty-cell character. |

## `tableId` is a persistence namespace, not a label

Column visibility, column order and density are written to `localStorage` under
`duncit-table-cols:<tableId>` and `duncit-table-density:<tableId>`. Two tables sharing a
`tableId` will fight over each other's column prefs, and a user who hid a column on one page
will find it hidden on the other. Prefix it with the portal (`finance-backout-refunds`,
`admin-users`) and never reuse it.

Storage is wrapped in try/catch on every read and write — private mode or a full quota simply
means prefs do not persist, not that the table breaks.

## `externalFilters` vs a column `filter`

Both narrow the query, and picking the wrong one produces a UI the user cannot explain.

- A column `filter` is **user-driven**: it renders a control in the filter popover and shows a
  removable chip. Use it for anything the user should be able to clear.
- `externalFilters` are **page-driven** — a tab, a URL param, a page-level select. They are
  compared by value, reset to page 1 when they change, and deliberately render **no chip**,
  because a chip the user can dismiss would drop the page's own scoping.

`ApolloTableFetchOptions.extraFilters` is the third variant: pinned filters applied inside the
fetch bridge, invisible to the table entirely. Use it for scoping the user must never see or
alter (tenant, ownership).

## Selection is per page, and it is a mirror

Passing `selection` adds AG Grid's own checkbox column. Leaving it off is the default and
costs the other tables nothing: with no prop, no `rowSelection` and no `onSelectionChanged`
reach the grid at all.

```tsx
const clearRef = useRef<(() => void) | null>(null);
const [selected, setSelected] = useState<EmailLogRow[]>([]);

<DuncitTable<EmailLogRow>
  …
  selection={{ onChange: setSelected, clearRef }}
/>;

// after a bulk delete:
await deleteEmailLogs({ variables: { ids: selected.map((row) => row.id) } });
clearRef.current?.();
refetchRef.current?.();
```

`onChange` hands you **the rows ticked right now**, and `useState` is the whole of the
correct parent state. Do not accumulate ids into a `Set` across pages. `DuncitTable` always
sets `getRowId`, so AG Grid runs its immutable update path and retention is BY ID: when new
rows arrive it deletes the nodes whose ids are gone, deselects those, and fires
`selectionChanged` with source `rowDataChanged`. A page turn drops the ticks and calls
`onChange` again — with `[]` when nothing survived. A `refetch()` that returns the same ids
keeps them ticked and fires nothing at all, so the objects you are holding are the
pre-refetch ones: act on their ids, not on the rest of their fields. An
accumulator would keep reporting "47 selected" while the grid shows 25 rows, and the bulk
action would hit rows the operator never saw. Selection is per page; if you need to act on
more, filter down and act page by page.

`clearRef` mirrors `refetchRef`: the table fills it, the parent calls it. It calls
`deselectAll()` on the grid, which is the only thing that actually unticks the checkboxes —
resetting the parent's array on its own leaves them checked. The deselect fires
`selectionChanged` too, so the parent's array empties through `onChange` and needs no second
reset. Like `refetchRef` it is nulled on unmount.

The header checkbox is **not** "select all". AG Grid's client-side row model only holds the
rows the server returned for the current page, so every `SelectAllMode` ticks that page.
Label it accordingly on screen.

Row clicks and ticks coexist: `enableClickSelection` stays at AG Grid's default `false`, and
`onRowClick` ignores anything inside the selection column. The checkbox stops propagation on
its own, but it is a 16px input in a 50px cell — without the column-level guard, aiming at
the tick box and missing would open your drawer with nothing selected.

Do not hand-roll a checkbox as a `DuncitColumn.cellRenderer`. `buildColDefs` marks renderer
columns never-equal to force repaints, so a checkbox driven by parent React state renders
stale ticks; AG Grid's generated selection column (`ag-Grid-SelectionColumn`) repaints off the
row node's own `rowSelected` event and is immune. Note also that AG Grid 34 removed
`rowSelection="multiple"`, `colDef.checkboxSelection` and `headerCheckboxSelection` — the
object form is the only API left.

## `makeApolloTableFetch` vs `useApolloTableFetch`

Same function; the hook wraps it in `useMemo`. Inside a component always use the hook — a fresh
`fetchRows` identity on every render re-triggers the table's fetch effect and the table loops.
The `deps` array lists the reactive values your `options` close over (the client, query and
`resultKey` identities are tracked for you). Use `makeApolloTableFetch` only outside React.

Neither takes an `@apollo/client` dependency: `TableGqlClient` is a structural type covering
just the `query` method, which a real `ApolloClient` satisfies as-is. Default fetch policy is
`network-only`, which is the only policy any table uses today.

If your server query takes legacy flat arguments instead of `TableQueryInput` (the support
portal lists), pass `buildVariables` to replace `tableQueryToGql` wholesale rather than
reshaping the state.

## Column helpers — use them instead of re-deriving cells

`dateColumn()` defaults to the hidden `created_at` column with a `d MMM yyyy` format
(`DEFAULT_DATE_FORMAT`) and an em-dash fallback for null. `formatDateCell(iso, format)` is the
same formatting on its own, and `EM_DASH` is the empty-value character every table uses so
blanks look identical across portals. `actionsColumn()` and `activeChipColumn()` cover the two
cell shapes that repeated most.

Dates go through `date-fns` (a peer dependency), never `toLocaleDateString` — rule 11.

## Peer dependencies and AG Grid registration

Everything heavy is a **peer**: `@mui/material`, `@mui/icons-material`, `@mui/x-date-pickers`,
`ag-grid-community`, `ag-grid-react`, `date-fns`, `react`, `react-dom`. The package itself has
no runtime dependencies, so it never pulls a second copy of React or MUI into a portal bundle.
A portal adding `@duncit/table` must already have those installed.

`src/agGridSetup.ts` calls `ModuleRegistry.registerModules([AllCommunityModule])` **once** at
package module scope, imported at the top of `DuncitTable.tsx`. Do not register AG Grid modules
again in a portal — a second registration is at best redundant and at worst a version conflict.

## The jsdom auto-height workaround

AG Grid's per-cell `autoHeight` measures real rendered layout so multi-line cells never clip.
jsdom reports no layout at all, and AG Grid silently drops every row past the first couple —
which looks exactly like a broken fetch in a test.

`DuncitTable` detects jsdom via the user agent and skips the measurement pass there. If you are
writing a table test and rows are missing, this is why the real browser and the test can differ;
it is a test-environment accommodation, not behaviour to depend on.
