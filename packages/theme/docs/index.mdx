## Why this exists

Every portal used to call `createTheme` in its own `main.tsx` with its own hex codes, its own
border radius and its own `MuiButton` override. Eighteen copies of "what a Duncit card looks
like" drift the moment one of them is touched: a slightly different border in dark mode, a
different `MuiPaper` elevation, a chip that is `rounded` here and `square` there.

Now there is one theme and one set of overrides. **Only the brand `accent` differs per portal.**
Everything else — ink, muted text, borders, the four surfaces, state tints and the overlay
shadows — is derived from `tokens` by `buildThemeCtx`, so no override file contains a literal
colour.

The look is a quiet, dense workspace: flat surfaces separated by hairlines, a single raised
layer for things that float (menus, popovers, dialogs), muted secondary text, and state shown
as a tint rather than a change of colour. Status chips and alerts are soft tints whose text is
darkened or lightened until it clears 4.5:1 on that tint.

## Use it

From `packages/shell/src/mountPortal.tsx`, which is how all eighteen portals get their theme:

```tsx
import { DuncitThemeProvider } from '@duncit/theme';

<DuncitThemeProvider
  accent={config.accent}
  storageKey={config.colorModeKey}
  extend={themeExtend}
>
  {children}
</DuncitThemeProvider>;
```

Reading or flipping the mode from a component (`packages/shell/src/chrome/AppHeader.tsx`):

```tsx
import { tokens, useColorMode } from '@duncit/theme';

const { mode, toggle } = useColorMode();
<IconButton onClick={toggle} sx={{ color: tokens.dark.ink }} />;
```

Derived values from four. The page is flat on purpose — no accent wash in the background, no

floats": only `raised` surfaces carry a `shadow`.

The light-mode counterparts of the same call:

```ts
const ctx = buildThemeCtx('light', financeAccent);
ctx.ink          // '#18181b'
ctx.bg           // '#f7f7f8'   sidebar + page ground
ctx.surface      // '#ffffff'   content panel, cards
ctx.soft         // '#f0f0f2'   table header, quiet fills
ctx.raised       // '#ffffff'   menus, dialogs
ctx.border       // '#e4e4e7'   hairline — decorative
ctx.inputBorder  // '#85868f'   field outline, 3:1
ctx.muted        // '#5f606a'   4.5:1 on paper, bg and soft
ctx.primary      // '#167e3c'   #22c55e darkened until it is 4.5:1 text on every light ground
ctx.primaryFill  // '#178640'   #22c55e darkened until white text on it is 4.5:1
```

### Any accent comes out WCAG AA

A portal may pass any brand colour — `#22c55e` above reads at 2.28:1 under white. `buildThemeCtx`
never lets that reach the screen:

| Context value | Rule | Used by |
| --- | --- | --- |
| `primary` | the accent mixed toward black (light mode) or white (dark mode) until it is **4.5:1 text** on every ground of the mode; unchanged when it already is | `palette.primary.main`, `palette.accent.main`, text buttons, the tab indicator, the selected row's icon and wash, input focus border and ring, the focus ring |
| `onPrimary` | white when it clears 4.5:1 on `primary`, otherwise `neutral[900]` | `palette.primary.contrastText` |
| `primaryFill` | the accent darkened until **white text** on it is 4.5:1 | contained buttons, filled primary chips, the "on" switch track |
| `primaryHover` / `primaryActive` | the portal's own `hover` / `active` when visibly darker, otherwise the previous step 10% darker — never lighter, so white stays above 4.5:1 | the fill's hover and pressed states |
| `semantic` / `onSemantic` | `tokens.semantic` + white in light mode, `tokens.dark.semantic` + `neutral[900]` in dark mode | `palette.success`/`warning`/`error`/`info`/`secondary`, alert tints, the required asterisk |

`palette.brand.main` is the portal's raw `accent.main`, for decoration only — a logo, an
illustration, a large display heading. Never body text, never a fill under text.

`scripts/verify-contrast.mjs` re-checks the token values in this package and in
`@duncit/auth-tokens` on every CI run and exits 1 when a pair drops under its threshold.

### Focus and motion

`MuiCssBaseline` spreads `focusVisibleGlobalCss(ctx.primary)` and `reducedMotionGlobalCss` from
`@duncit/buttons`: every link, button, ARIA widget, `tabindex="0"` element and MUI `ButtonBase`
gets a 2px ring 2px outside it, and `prefers-reduced-motion: reduce` collapses transitions and
animations (progress indicators excepted).

### The built theme

```ts
const theme = createDuncitTheme('dark', financeAccent);

theme.palette.mode        // 'dark'
theme.palette.primary     // { light: '#86efac', main: '#22c55e', dark: '#136d34', contrastText: '#18181b' }
theme.palette.accent      // { main: '#22c55e', contrastText: '#18181b' }   ← red/accent TEXT
theme.palette.brand       // { main: '#22c55e' }                            ← decoration only
theme.palette.background  // { default: '#101116', paper: '#16171d' }
theme.palette.text        // { primary: '#ececef', secondary: '#9c9fa8',
                          //   disabled: 'rgba(255, 255, 255, 0.5)', icon: 'rgba(255, 255, 255, 0.5)' }
theme.palette.action      // hover / selected = the ink tints above, so MUI's own states match
theme.shape.borderRadius  // 6   — tokens.radius.sm
theme.shadows             // 0 → 'none', 1–2 → raised, 3–12 → overlay, 13–24 → dialog
theme.transitions.duration // { shortest: 120, shorter: 120, short: 180, standard: 180, complex: 240, … }
theme.typography.fontFamily
// '-apple-system, BlinkMacSystemFont, "Segoe UI Variable Text", "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif'
theme.typography.h5       // { fontSize: '1.25rem', fontWeight: 600, … }   ← a page title
```

No web font ships with the shell: the console renders in the platform UI face, so nothing is
downloaded before first paint. An admin-picked family (Admin → Branding → Portals) still layers
over it at runtime.

48 components are overridden — this is the list a portal inherits without asking:

```

MuiAccordion, MuiAccordionSummary, MuiDialog, MuiDialogTitle, MuiDialogContent,
MuiDialogActions, MuiBackdrop, MuiDrawer, MuiPopover, MuiMenu, MuiMenuItem,
MuiAutocomplete, MuiDivider, MuiButton, MuiIconButton, MuiTextField, MuiSelect,
MuiFormLabel, MuiFormHelperText, MuiInputBase, MuiOutlinedInput, MuiSwitch, MuiChip,
MuiTooltip, MuiTable, MuiTableHead, MuiTableCell, MuiTableRow, MuiTablePagination,
MuiListItemButton, MuiListItemIcon, MuiListSubheader, MuiAlert, MuiAlertTitle,
MuiAvatar, MuiSkeleton, MuiLinearProgress, MuiTabs, MuiTab, MuiToggleButton,
MuiBreadcrumbs, MuiPaginationItem
```

A few of them decide how a whole console reads:

- **Buttons** come in three weights. `contained` primary is the one action (accent fill);
  `outlined` is the neutral secondary (ink on the surface, quiet edge); `text` is inline.
- **Filled status chips** (`success`/`warning`/`error`/`info`/`secondary`) and **standard
  alerts** are soft tints; the filled `primary` chip stays solid because it usually marks a
  selection.
- **The selected list row** is an accent wash + semibold ink + an accent icon — three cues, so
  it never rests on colour alone.
- **Placeholders** are `muted` at full opacity, which clears 4.5:1 (MUI's 42% does not).
- **Switches** are compact pills whose "off" track is the 3:1 field-outline colour.

`MuiTableHead` tints the header row, and that tint is **opaque in both modes**.
It has to be: a `stickyHeader` table paints its header over the rows scrolling
underneath it, and a translucent tint lets every one of those rows read through
the column titles. If you override it, keep the colour opaque.

`extend` adds to that set rather than replacing it:

```ts
const crmTheme = createDuncitTheme('light', crmAccent, () => ({
  MuiDataGrid: { styleOverrides: { root: { border: 0 } } },
}));
Object.keys(crmTheme.components).includes('MuiDataGrid');  // true
```

`touchTarget: 44` and `drawerWidth: 244` are in here for the same reason the colours are: a
portal that hardcodes `44` is a portal that will not follow when the token moves.

## API

| Export | Signature | Default | Meaning |
| --- | --- | --- | --- |
| `createDuncitTheme` | `(mode?: ColorMode, accent?: AccentColors, extend?: ComponentExtend) => Theme` | `'light'`, `tokens.defaultAccent`, — | Build the shared MUI theme. |
| `buildTheme` | alias of `createDuncitTheme` | — | Back-compat name some portals import. |
| `buildThemeCtx` | `(mode: ColorMode, accent: AccentColors) => ThemeCtx` | — | The derived context every override builder reads. |
| `buildComponents` | `(ctx: ThemeCtx, extend?: ComponentExtend) => Components` | — | The 21 overrides, plus anything `extend` adds. |
| `DuncitThemeProvider` | React component | — | Theme + `CssBaseline` + persisted colour mode. |
| `useColorMode` | `() => { mode, toggle, set }` | `{ mode: 'light', … no-ops }` outside a provider | Read and flip the mode. |
| `tokens` | `Tokens` (const object) | — | Colours, radii, sizes, fonts. The only place a literal lives. |
| `AA_TEXT` | `4.5` | — | WCAG AA minimum for normal-size text. |
| `contrastRatio` | `(a: string, b: string) => number` | — | WCAG contrast ratio (1–21) between two `#rgb` / `#rrggbb` colours. |
| `mix` | `(from: string, to: string, weight: number) => string` | — | `from` mixed toward `to` by `weight` (0–1), as `#rrggbb`. |
| `textOn` | `(fill: string, ink: string) => string` | — | White when it clears 4.5:1 on `fill`, otherwise `ink`. |

The four contrast helpers are what the theme itself uses to make an accent AA-safe. Admin →
Branding → Theme tokens reuses them to show each token's contrast and to derive the hover and
pressed steps from a new primary colour:

```ts
import { contrastRatio, mix, textOn } from '@duncit/theme';

contrastRatio('#d92d2d', '#ffffff'); // 4.81
mix('#2563eb', '#000000', 0.1);      // '#2159d4' — one step darker
textOn('#facc15', '#16181d');        // '#16181d' — white fails on yellow
```

### `DuncitThemeProvider` props

| Prop | Type | Required | Default | Meaning |
| --- | --- | --- | --- | --- |
| `accent` | `AccentColors` | no | `tokens.defaultAccent` | The portal's brand accent. |
| `storageKey` | `string` | no | `'duncit_color_mode'` | localStorage key for the mode — **must be unique per portal**. |
| `defaultMode` | `'light' \| 'dark'` | no | `'dark'` | Mode on first load when nothing is stored. |
| `extend` | `ComponentExtend` | no | — | Extra MUI overrides needing a portal-only dependency. |
| `children` | `ReactNode` | yes | — | The app. |

### `AccentColors`

| Field | Type | Required | Used for |
| --- | --- | --- | --- |
| `light` | `string` | yes | `palette.primary.light`, `ctx.primaryLight` |
| `main` | `string` | yes | made AA-safe into `ctx.primary` (text) and `ctx.primaryFill` (fill); raw as `palette.brand.main` |
| `hover` | `string` | yes | `ctx.primaryHover`, when darker than the fill |
| `active` | `string` | yes | `palette.primary.dark`, `ctx.primaryActive`, when darker than hover |

`ColorMode` is MUI's `PaletteMode` (`'light' | 'dark'`). `ComponentExtend` is
`(ctx: ThemeCtx) => Components<Theme>`, merged over the shared set.

## Do not call `createTheme` in a portal

`DuncitThemeProvider` already builds the theme, applies `CssBaseline` and provides the colour
mode. A portal that calls `createDuncitTheme` and wraps its own `ThemeProvider` gets a second
theme object and loses the persisted mode toggle.

`createDuncitTheme(mode, accent, extend)` is for tests, Storybook-style previews, and the
provider itself. `buildTheme` is a **back-compat alias for the same function** — portals
historically imported that name. Prefer `createDuncitTheme` in new code; do not treat them as
two variants.

## `extend`, not a fork

A portal that needs an override requiring its own dependency — CRM's `MuiDataGrid` is the live
case — passes `extend: (ctx) => ({ MuiDataGrid: … })`. It receives the same derived `ThemeCtx`,
so the one-off override uses the same ink, border and surface values as everything else, and
the shared package never grows a dependency only one portal has.

The extend result is spread **last** in `buildComponents`, so it wins over the shared overrides
for the same component key. That is deliberate, and also why it should stay small: an `extend`
that redefines `MuiButton` has re-introduced exactly the drift this package removed.

## `storageKey` must be unique per portal

The chosen mode is persisted to `localStorage` under `storageKey` (default
`duncit_color_mode`). All portals are served from `*.duncit.com` subdomains, so two portals
sharing a key would only be an issue on a shared origin — but tests share one jsdom origin,
which is why every shell test passes its own key (`hdr_light`, `shell_test`). Pass
`config.colorModeKey`, never the default.

`defaultMode` is `'dark'`. It applies only on first load when nothing is stored.

## Never hardcode a colour or a size

`tokens` is the single source of truth: the neutral ramp, the semantic status colours, light
surfaces, their dark counterparts, radii and fonts. Component styles read them through
`ThemeCtx` (`ctx.ink`, `ctx.border`, `ctx.surface`, `ctx.raised`, `ctx.hover`, `ctx.shadow`,
`ctx.transition`), which
`buildThemeCtx(mode, accent)` computes once per theme build.

If you need a colour in a portal, take it from `tokens` or from the MUI theme — a hex literal
in a `sx` prop is the drift starting over. If the value genuinely does not exist yet, add it to
`tokens` so every surface gets it.

## Scope: consoles only

This is the **console** design system. mWeb and the public Astro websites are deliberately not
consumers — mWeb has its own MUI theme, and the native app uses Tamagui (rule 29). Do not
import `@duncit/theme` into either; the token values are tuned for dense admin surfaces, not
for the member-facing product.

## Coverage

`vitest.config.ts` sets 100/100/100/100 with `src/index.ts` and the `src/**/index.ts` barrels
excluded. Adding a component override means adding the test that renders it in both modes —
every override builder branches on `ctx.isDark`, so a light-only test cannot pass the gate.
