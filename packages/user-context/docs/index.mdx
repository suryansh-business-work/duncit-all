## Why this exists

Every portal's `main.tsx` used to declare its own `SessionMe` query, its own `loadUser`, its own
`localStorage` user cache and its own logout that guessed at which keys to clear. Nineteen
copies of "who is signed in" is nineteen places for a stale cache, a missed field or a logout
that leaves a token behind.

`UserProvider` hydrates from `localStorage` **synchronously** on mount, so a refresh never
flashes a logged-out shell before `me` resolves — that flash was the visible symptom the copies
each fixed differently, or not at all.

## Use it

`packages/shell/src/mountPortal.tsx` wires it for all eighteen portals; `app/mweb/src/main.tsx`
does the same by hand:

```tsx
import { UserProvider, PortalModeGate } from '@duncit/user-context';

const isAuthed = () => !!localStorage.getItem(config.tokenKey);

<UserProvider isAuthed={isAuthed} loadUser={loadUser} storageKey="mweb_user">
  <PortalModeGate portalKey="mweb" graphqlUrl={urlConfigs.graphqlUrl} appName="Duncit">
    <App />
  </PortalModeGate>
</UserProvider>;
```

`loadUser` comes from the shared bootstrap rather than a hand-written query:

```ts
import { createSessionUserLoader } from '@duncit/user-context';

// portals/crm/src/main.tsx — the default SessionMe selection
const loadUser = createSessionUserLoader(apolloClient);

// portals/partners-app/src/main.tsx — same selection, own operation name
createSessionUserLoader(apolloClient, { operationName: 'PartnerSessionMe' });

// portals/admin/src/main.tsx — a genuinely richer query
createSessionUserLoader(apolloClient, { query: ADMIN_ME });
```

Reading the user in a component (`packages/shell/src/chrome/ProfilePage.tsx`):

```tsx
import { useUserData } from '@duncit/user-context';

const { user, refetch, logout } = useUserData();
```

## `update` vs `refetch` vs `setUser`

Three ways to change the user, and picking wrong either wastes a round trip or shows stale data.

- **`update(patch)`** — local-only merge, persisted to `localStorage`. **Does not call the
  server.** Use it after a mutation that already returned the new value.
- **`refetch()`** — re-runs `loadUser`, refreshing both memory and the cache. Use it when the
  server changed something you did not receive back.
- **`setUser(user)`** — wholesale replacement, e.g. straight after login. `setUser(null)` clears
  without redirecting.
- **`logout()`** — `clearAllStorages()` plus navigation to the login page. It wipes
  `localStorage` **and** `sessionStorage` entirely; no preference survives a logout, by design.

## Same-tab login needs `emitAuthChanged`

A portal logs in with a client-side navigation, no page reload. `UserProvider` is mounted once
above the router, so it never re-runs its initial load and the header and sidebar stay empty
until the user manually refreshes. `storage` events do not help — they only fire in *other* tabs.

So the session helpers dispatch `AUTH_CHANGED_EVENT` (`'duncit:auth-changed'`) on the window
whenever the token is set or cleared, and the provider reloads. Any code path that writes or
removes the auth token must call `emitAuthChanged()`; `packages/shell/src/lib/session.ts` is the
reference call site.

## `PortalModeGate` fails open on purpose

The gate polls `portalMode(key:)` every 60s with a plain unauthenticated `fetch` — no Apollo
dependency — and swaps in `MaintenanceScreen` or `UnderDevelopmentScreen` when the Tech portal
takes a portal off Live.

Any network error keeps the app **rendered**. A server blip must never lock every user out of
every portal simultaneously, which is exactly what a fail-closed gate would do. It also re-polls,
so apps recover on their own when set back to Live without anyone reloading.

## The login form is still Formik + Yup

`login.form.tsx` uses `useFormik` and `yup`, and `formik`/`yup` are declared peer dependencies.
That predates rule 30 (React Hook Form + Zod) and is the one place in the shared packages that
has not migrated. Do not copy this pattern into a new form, and do not add a *second* form here
in the old style — a migration of this file is its own change, with `login.form.cy.tsx` updated
alongside it.

`loginSchema` and `loginInitialValues` are exported so a surface can reuse the validation
without the screen; `LoginScreen` is the full page, `LoginForm` just the fields.

## `buildSessionMeQuery` — extend, do not fork

The default selection is `user_id`, `full_name`, `first_name`, `last_name`, `email`, `roles`,
`locale`, `profile_photo`. Need more? Pass `extraFields`, which appends to that selection. Only
pass a full `query` override when the shape genuinely differs (admin's richer `ADMIN_ME`); a
hand-written `me` query in a portal is how a field ends up missing on one surface only.

The loader is `fetchPolicy: 'network-only'` — the `localStorage` cache is the fast path, so
serving `me` from the Apollo cache on top of it would just be a second layer of staleness.

## Storage is always guarded

`readCachedUser`, `writeCachedUser` and `clearAllStorages` all check `globalThis.window` and wrap
every access in try/catch. Private mode, a blocked origin, a full quota or corrupted JSON all
degrade to "no cache", never to a thrown error at mount. Corrupted JSON is additionally *removed*
so the next write replaces it cleanly. Do not touch `localStorage` for the user object directly —
go through these.

Coverage is gated at 100/100/100/100, with `src/types.ts` and the `*.cy.tsx` Cypress component
tests excluded (those run under Cypress, not vitest).
