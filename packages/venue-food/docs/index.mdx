## Why this exists

A venue that serves food lists a menu, takes QR orders, gives its own coupons and wants to know
how its food is doing. Those four tools used to live only in the Partners console — and the menu
had a second copy in the Venues console's venue editor. The owner also works from mWeb and the
app, and the Venues console's editors look after the same venues — so the tools are one package,
mounted by every web surface, instead of copies drifting apart.

The native app draws the same tools with Tamagui (`app/mobile-app/src/components/venue-food-desk/`,
the menu under `menu/`). It cannot import this package (MUI), so everything that is not drawing
lives below it:

- **`@duncit/utils` → `venue-food-owner.ts`** — the desk's GraphQL documents as plain strings, the
  row types, the status flow, the chip colours, every label builder (`foodDietLabel`,
  `foodSpiceLabel`, …), the dashboard tiles, bars and trend line.
- **`@duncit/utils` → `venue-food-menu.ts`** — the menu's documents (`OWNER_FOOD_MENU_QUERY`,
  `ADMIN_FOOD_MENU_QUERY`, `FOOD_MENU_CONFIG_QUERY`, `UPDATE_VENUE_FOOD_MENU_MUTATION`,
  `FOOD_RAZORPAY_CONNECTIONS_QUERY`), its form values (`FoodMenuFormValues`) and both mappings
  (`foodMenuToValues`, `toFoodMenuSaveInput` / `toVenueFoodInput`), `canTakeFoodOrders`.
- **`@duncit/forms/schemas`** — `makeFoodMenuSchema` / `makeVenueFoodRefinement` (the menu),
  `makeFoodOrderCancelSchema`, `makeFoodCouponSchema` with `foodCouponToValues` /
  `toFoodCouponInput`, so a dish, a reason or a coupon is refused the same way everywhere.

## What each tool does

- **`VenueFoodDashboard`** — the venue's food numbers for a period (7 / 30 / 90 days or all time):
  the tiles, orders by status, top dishes, the daily trend (inline SVG with a numbers table for
  screen readers) and recent feedback.
- **`VenueFoodMenu`** — the menu editor: "serves food", the dishes (name, section, description,
  price, food type, spice level, available today, photos), QR ordering (the switch, the discount,
  the venue's own GST) and the GST number on the food invoices. RHF + `makeFoodMenuSchema`, saved
  through `updateApprovedVenue`; a save re-opens the form on the server's copy, so a new dish keeps
  the id it was given. Only an approved venue's menu is edited here — before that it lives in the
  venue form (`notApprovedAction` says where).
- **`VenueFoodOrders`** — the paid-order board on `@duncit/table`: move an order along the kitchen's
  path, read it in full (with the guest's rating and photos), or cancel it with a full refund. It
  asks again every 20 seconds, paused while a dialog is open.
- **`VenueFoodCoupons`** — the venue's coupons on `@duncit/table`: create and edit (RHF + Zod),
  switch on and off (optimistic, put back on a refusal), delete after a confirm.

### The food fields, for a bigger venue form

`VenueFoodFields` is the menu editor's body on its own — the switch, the dish list, the ordering
fields — generic over any react-hook-form form that holds the food block under the standard names
(`offers_food`, `food_menu`, `food_ordering`). The Partners venue form's Food section and the
Venues console editor's Food Menu section mount it, so there is ONE dish list and ONE set of
ordering fields; their schemas use the shared `makeVenueFoodRefinement` and their saves the
shared `toVenueFoodInput`. `FoodGstinField` is the invoice GST number, passed in as `gstin`
because each form names and locks it its own way. `showMenu={false}` leaves the dish list out —
the Partners console's Food Settings page sets up everything else (licences, ordering, GST
number, tables) while Food > Menu stays the one place that edits the dishes.

```tsx
<VenueFoodFields
  control={form.control}
  config={config}
  account={{ kind: 'status' }}
  upload={{ venueId, surface: 'PORTALS' }}
  idPrefix="venue-editor"
/>
```

### The Razorpay account, per surface

The account guests pay is the owner's own saved connection (`PartnerIntegration`). `account`
says how a surface handles it, and `sendsFoodAccount(account)` decides whether a save names it:

| `account` | Draws | A save |
| --- | --- | --- |
| `{ kind: 'picker', addAccount? }` | the owner's connections (`myPartnerIntegrations`), plus the surface's own way to add one | names the picked account (`null` unlinks) |
| `{ kind: 'status', manageHref? }` | whether one is linked (`razorpay_linked`), read-only, and where to change it | never names it — the link is left alone |

Ordering can be switched ON only with an account (picked and connected, or linked) and an
available dish — the gate the server applies; it can always be switched off.

### The GST number

An owner gives a venue its GST number once; a saved one is shown locked (the server refuses an
owner's change). In `mode="admin"` a Venues console editor may change it — the server lets a
console editor (`consoleEditors('VENUE')`) use `updateApprovedVenue` on any approved venue.

### Dish photos

Picked with `@duncit/media-picker` (images only), filed in the venues media folder
(`FOOD_PHOTO_FOLDER`, `/venues`) with the venue as the upload's entity — the server files them
under `/{env}/venues/{venue id}/media`.

### Videos (dishes and the venue)

`VideoLinksField` is one list of videos — each an uploaded clip (the picker's video upload, the
ImageKit direct-upload + compression pipeline) or a YouTube link (`makeYoutubeLinkSchema`,
`@duncit/regex` `YOUTUBE_URL`). Every dish card has one (`food_video_limit`), and the Partners venue
form and the Venues console editor mount the same field for the venue's own `videos`
(`venue_video_limit`). The kind is read from the address (`venueVideoOf` in `@duncit/utils`).

### Struck-through MRP

Each dish may carry an `original_price` above its `price`, and a `saving_display` (`PERCENT` →
"20% off", `AMOUNT` → "₹40 off"). `FoodDishPricing` shows the line the guest will see, through
`foodPriceDisplay` / `foodSavingLabel` (`@duncit/utils`). Display only — the guest is always
charged `price`; the server refuses an MRP at or below it.

### Licences and tables

`FoodLicenceFields` holds the FSSAI number (14 digits, `@duncit/regex` `FSSAI_NUMBER`; printed at
the foot of the public menu and on food invoices) and the optional liquor licence number, each with
an optional uploaded document that only the owner and Duncit see. `FoodTablesFields` lists the
venue's tables (typed, or filled in from a count) and downloads every table's QR sticker in one PDF
(`myVenueTableStickersPdfBase64`) — each QR opens the menu with `?table=<label>`, which the guest's
checkout fills in. The stickers print the SAVED tables, so the button waits for a save
(`hasSavedTables`).

## Use

Each tool takes the venue it is about. Picking the venue — and what to show for one that serves no
food — stays with the page that mounts it.

```tsx
import { VenueFoodCoupons, VenueFoodDashboard, VenueFoodMenu, VenueFoodOrders } from '@duncit/venue-food';
import { logs } from '@duncit/logs';

<VenueFoodDashboard venueId={venue.id} logger={logs.mWeb} />
<VenueFoodMenu venueId={venue.id} surface="mweb" mode="owner" account={{ kind: 'picker' }} uploadSurface="MWEB" logger={logs.mWeb} />
<VenueFoodOrders venueId={venue.id} surface="mweb" />
<VenueFoodCoupons venueId={venue.id} surface="mweb" />
```

- `surface` prefixes the tables' ids (`<surface>-venue-food-orders`) and the menu's test ids, so
  each surface remembers its own column choices.
- `logger` is the mounting surface's logger; a failed retry is filed against it.
- `FOOD_OWNER_VENUES` is the owner's venues with `offers_food`, for the host page's venue picker.

## Where it is mounted

| Surface | Where | Venue selection |
| --- | --- | --- |
| Partners console | `/venues/food-dashboard`, `/venues/food-menu`, `/venues/food-orders`, `/venues/food-coupons`; the venue form's Food section (`VenueFoodFields`) | `VenueStudioBody` (remembered pick) |
| Venues console | the venue record's Food Menu tab (every venue, `mode="admin"`) and Food dashboard / Food orders / Food coupons tabs (URL `selectedtab`, only when the venue serves food); the venue editor's Food Menu section (`VenueFoodFields`) | the record being viewed |
| mWeb | `/venues/food-dashboard`, `/venues/food-menu`, `/venues/food-orders`, `/venues/food-coupons` | `VenuePageFrame` + `useSelectedVenue` |

## Copy

Every sentence is a `venueFoodOwner.*` key (`packages/i18n/src/bundles/venue-food-owner.ts`),
spread into the shell, mWeb and native fallbacks. The GST field labels are `shell.foodTax.*`
(mWeb and native ship that branch alone: `SHELL_FOOD_TAX_SLICE`).

## Tests

The package has no suite of its own (like `@duncit/public-page`): its logic is tested where it
lives — `packages/utils/__tests__/venue-food-owner.test.ts`, `venue-food-menu.test.ts` and
`packages/forms/__tests__/schemas.food-*.test.ts` (all 100% gated) — and the components are
exercised by the Partners console's venue form and coupon page suites and the Venues console
editor's section suite (`packages/entity-consoles/.../sections.food-to-leaves.test.tsx`).
